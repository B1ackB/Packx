# 工作台教程浏览器回归

在仓库根目录运行：

```sh
npm ci --ignore-scripts
npx --no-install playwright install chromium --only-shell
npm run test:browser
```

依赖已安装时只需最后一行。首次准备需要下载固定版本的浏览器；测试本身使用本机前端和合成 API 数据，不需要模型、密钥、原生解析器或运行中的 Packx 服务。

`playwright.config.ts` 自动启动并关闭 `127.0.0.1:4178` 的 Vite 服务。端口占用时明确失败，不接管现有服务；常用的 `dev:fixture` 端口不受影响。浏览器回归独立于 `npm run check`，前者验证真实浏览器交互，后者继续验证单元测试、类型与构建。浏览器测试和配置也纳入 TypeScript 检查。

## 覆盖范围

同一组 6 个场景在 Chromium 的三个配置下执行，共 18 项：桌面中文 1440×1000、窄屏中文 390×844、窄屏英文 320×568。

| 场景 | 断言 |
| --- | --- |
| 退出按钮、Esc、最后一步完成 | 原生模态窗关闭，焦点回到可见教程入口；再次开启从第一步开始 |
| 三种退出路径的输入保留 | 未发送的多行对话、未提交的字段选择/数量/单位、记忆主题/多行内容/到期日完整保留 |
| 键盘导航 | 初始标题获得焦点，Tab/Shift+Tab 在教程按钮间循环，首步禁用上一步，方向键及按钮切换步骤 |
| 页签与工作区 | 首步展示对话，后续自动切到需求单；退出恢复原记忆页签与工作区、会话侧栏的开闭状态；原本关闭的面板不被留下打开 |
| 来源面板 | 教程临时打开的字段区与来源区在退出后还原，用户预先打开的来源区继续保持打开 |
| 所有场景 | 浮窗在视口内，页面无未捕获错误；禁止非 GET 请求、未登记 API 和外部 HTTP 请求 |

测试只操作教程及未提交的表单，不发送消息、确认 Fact、批准版本或导出文件。API 响应与当前 TypeScript 合同对齐，并通过请求拦截提供；不会读取或写入 `.blackx-data`。这验证的是浏览器中的交互与输入状态，不替代服务端业务闭环、真实模型质量、多浏览器、读屏器或实体触屏验收。

`customerCopy.spec.ts` 另外提供两类文案回归，在上述三个配置下执行六项检查。覆盖展开后的需求单、来源识别提醒、模板、错误及模型处理记录；确认内部编号与技术详情不显示，原文、待确认状态仍保留。资料导入覆盖无效资料包、重新选择、按附件名称读取，以及与原请求内容一致的模拟提交。所有提交均由测试拦截，不调用真实后端；同时检查窄屏溢出并保存页面截图。模板库另有一个交互场景，在三个配置下共三项：模拟保存已成功但响应丢失，检查新建及更新重试沿用请求编号、修改操作使用新编号、刷新恢复填写设置、重新预览与确认、交付历史及失效下载禁用。目录读取不产生写请求，保存/生成/下载均由用例拦截，不接触真实后端。连同教程共 27 项浏览器检查。

## 定位失败

```sh
npm run test:browser -- --project=narrow-en
npm run test:browser -- --grep Escape
```

失败截图、调用轨迹和断言上下文写入已忽略的 `temp/browser-tests/`。用测试输出中给出的 `trace.zip` 路径执行 `npx --no-install playwright show-trace <路径>`。测试不自动重试，不使用固定等待掩盖交互问题。

2026-10-12 本机验证：18 项浏览器回归通过，原有 20 个未提交文件保持逐字节不变。
