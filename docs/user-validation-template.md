# 待真实条件具备后的用户验证记录

协议：`requirement-review-pilot.v1`（2026-09-26）。状态：**真实用户试用未执行**；参与者、获授权素材与运行预算待落实。产品已提供原文核对和试用记录入口，不能把离线演示填成真实试用。

## 本轮要回答的问题

包装售前／跟单收到客户聊天、附件与后续修改后，Packx 能否减少整理、逐项核对和返工所需时间，同时交付接收岗位可使用的需求单？首轮只验证这一个任务，不评价生产文件精度或自主成交。

输入是一笔订单的有序资料与变更。输出是版本化需求单，包含已确认值、可追溯来源、缺失项、未确认提议以及旧交付失效说明。成功需要同时满足：

- 七个必填字段准确或明确指出缺失；已提供的可选字段不遗漏，未提供的可选规格不补造。
- 数量、尺寸／单位、日期／交付口径、材料与版本无关键错误；冲突和新提议不得覆盖已确认事实。
- 必要确认和审批没有跳过；接收岗位在对照来源后判定可继续跟单。明确要求补资料且指出缺口，可以是正确的任务结果。
- 中途放弃、服务失败、无法验收计入分母；不能只统计成功导出的需求单。

正确字段、允许等价表述、缺失项与关键错误定义应由有业务知识的人在运行前冻结，不能由被测模型自己给自己评分。首次试用建议 3–5 位参与者、10–20 个订单；这是探索性规模，不足以推广为企业总体成功率。没有真实材料时用新编合成订单，报告必须注明。

## 对照与冻结

第一轮比较现有人工方法和 Packx；预算允许时再增加同模型普通聊天。同一来源、交付要求和人工验收规则保持一致，记录实际模型标识、日期、采样配置、工具权限、超时、上下文策略和费用上限。若普通聊天只得到预提取文本，要披露与 Packx 读取原附件的差异，不能将该差异归因为 Harness。

将难度相近的订单分组并交错分配，避免同一人先做过订单再用另一方法重复，造成记忆优势。接收岗位尽可能不知道输出方法；实际操作者能看到 UI，不能称为双盲。人员、独立订单数与重复运行数分别报告。

已有 RI-01～RI-16 为作者可见资产；其中四个预留案例也不能包装成独立盲测。2026-09-25 的 Trial C 仍是当时版本的历史结果。本轮新增 `pendingChanges`，使有待确认变更的 `nextAction` 明确为 `confirm_facts`；新协议必须披露这个完成条件变化，保留旧 oracle 与旧评分，不能覆盖旧报告或凭新测试推导新的真实模型成功率。

## 记录入口与时间口径

在需求单中展开「记录一次试用」，填写样例编号、人员代号和素材类型，然后开始核对计时。等待模型、休息和处理其他工作时暂停；离开窗口会自动暂停，返回后需手动继续。修正数、关键错误数和验收结果由核对者填写，不从确认次数或审批状态推导。

- 界面计时仅覆盖人工手动计时的核对区间；不包含首次导入前的准备，也不等于整个任务耗时。长时间停留在页面仍会计时，应在观察记录中注明偏差。
- 尚未生成需求单就失败的任务没有可绑定的交付版本，不能使用这个核对计时入口；仍须在任务表登记为失败或放弃并纳入总分母，不能据界面保存的记录数倒推全部尝试数。
- 从收到素材到交接的总墙钟时间另用下面的表记录，包含阅读、等待、修订和导出。模型运行延迟单列，不与可能重叠的人工时间直接相加。
- 保存产生 `requirement-review-trial.v1` 不可变记录，绑定被核对的需求单版本、保存时的任务版本、操作者和运行指标快照。保存不改变 Fact 或 Approval。下载 JSON 留档；草稿切换任务会丢失，刷新页面前有未保存提示。
- POST `/api/conversations/:id/requirement-brief/trial-observations` 保存；GET 同路径加 `/:observationId` 重取。相同编号和内容重试返回原记录，内容不同则冲突；需要修订时保留原记录并另记修订原因，不抹去失败。
- 记录受现有本地身份与 tenant/workspace 边界保护，不是公开链接。运行指标快照是整个 Run 累计，不能当成这一个核对区间的耗时／费用。
- 「原样确认比例」是模型提议被原样确认的比例；「引用填写率」只检查是否填有引用。API 为兼容仍保留 `confirmedCandidateAccuracy`、`sourceCoverageRate` 字段名，它们都不是独立准确率。

## 开始前

取得素材使用授权并脱敏，保留来源和正确答案由谁确认的记录。不要把企业凭据或敏感客户原文提交到仓库。真实模型调用另行确认 Provider、数据去向和费用预算。

## 首轮报告与继续投入的条件

保留逐任务原始表、JSON、来源授权记录、交付版本、失败说明及验收人。汇总同时报告任务完成数／总数、关键错误任务数、人工修正字段数、人工核对时间与总墙钟时间的中位数和范围。数据未记录就标为缺失，不能用 0 代替。

每成功任务成本以全部已运行任务的已知模型成本之和除以成功任务数计算，包含失败尝试；若任何费用未知，明确标为不完整估算，不能当成真实账单。没有成功任务时该指标未定义。按独立订单展示配对结果，不将多次运行当成更多独立客户。

本轮预先采用的决策门槛：确认后交付不得含未发现的关键错误；在相同验收质量下观察人工核对与总墙钟时间是否改善；至少记录三条参与者说明的具体省事／返工原因。任一关键错误穿透确认，应先修复并增加回归，再谈速度收益。小样本没有稳定优势时如实报告，优先修复最常见失败，不扩展通用平台。

## 判断规则

- 无权威来源的字段不能计为“提取正确”。
- 总耗时包含阅读、核对、等待、修订和导出，不只统计模型响应时间。
- 样本数、参与人数、失败任务都如实记录；缺失数据留空。
- 合成验收只能证明对应工程行为；不填入真实用户统计。
- 下一个岗位认为交付物不可用时，记录原因并调整字段或流程，不直接调低完成标准。
