# 句子完整性与上下文补齐对照（v2）

本轮响应“完整句子分块、超长句关联、检索后补齐上下文都实验”的要求。新增实现位于独立评测适配器，继续使用 KnowledgeStore 的真实本地 E5 索引和服务端来源读取，不改 Agent Core、业务库、Fact 或 Approval。无新依赖或付费模型调用。

## 控制条件与候选

沿用 v1 的 5 篇 CC BY 研究全文、4 个文档家族、64 道已观察的中英文问题、56 道暂定有出处题、8 道无答案/过滤题。题目和原文位置标签未变，无人工黄金标注。E5 版本、q8、384 维、查询处理、字段 IDF、RRF、候选 K=8 和 Top-5 诊断均固定。

| 候选 | 建索引的方式 | 返回给上下文的内容 |
| --- | --- | --- |
| current-1000 | 当前约 1,000 字符 | 原块 |
| previous-500 | 上轮约 500 字符 | 原块 |
| whole-sentence-500 | 按完整句子组合，500 字符为目标 | 原块；单个超长句完整保留 |
| long-sentence-linked | 同上；超过 500 字符的单句再按 128 token、最多重叠 32 token 拆分 | 普通块原样；超长句子块还原为同一句父文本 |
| 500-restore-sentence | 上轮 500 字符索引 | 把命中块两端补到完整句子的边界 |
| 500-restore-paragraph | 上轮 500 字符索引 | 取回命中块所在的完整原始段落，包含同段相邻句 |
| linked-restore-paragraph | 句子组合 + 超长句关联索引 | 取回完整原始段落 |

表格仍按每行一块，完整保留表头、单位、脚注和条件。正文不跨原始段落；上下文补齐不跨文档、资料版本或段落，不凭模型猜测“哪个邻段必要”。完整原段落是本次对邻近上下文的保守实现，更远的相邻段落未纳入。

句子切分采用 Node 的 `Intl.Segmenter`，固定 Node v24.14.0 / ICU 78.2，并加入明确的缩写保护表（如 Dr.、Fig.、e.g.、i.e.、et al.）。测试发现原生切句会将 `Dr. Smith` 和 `e.g. PLA` 拆开，因此不能将原生 API 等同于语义完整性保证。该保护表仍不代表已覆盖所有专业缩写。

## 评分与权限边界

主指标为混合检索下 **1,024 E5-token 预算内完整证据包覆盖率**。仍使用 v1 的原句/表格来源范围，对所有候选统一忽略空白字符间隙，避免上轮已经发现的边界空格误罚；不修改 v1 历史分数。原文锚点 Recall@5 和 MRR@5 衡量扩展前的检索排名。

按原排名打包完整片段，完全相同的来源范围去重，放不下则跳过，不把超预算父段落重新截短后冒充完整。预算包括正文、表格、标题、型号、版本、链接、定位、补齐范围和新增来源 ID。它是上下文大小的固定代理，不是某个生成模型的计费 token。

同一个索引的三种输出方式共享同一次检索结果；补齐函数完全不接收题目或答案标签。四种索引各运行关键词、向量、混合三条路径，实际执行 4 × 3 × 64 次检索；七种输出方式共有 7 × 3 × 64 组评分。查询共享关系和实际模型用量在报告中明确记录，不能把复用说成增加了调用效果。

补齐的所有源块均通过 `KnowledgeStore.readEvidence` 再次执行租户、工作区、文档状态与日期过滤，核对同一文档版本、内容哈希和源块正文；读完关联块后重读锚点。越权、撤回、版本错配或源块不完整时失败，不从未经权限检查的父文本直接返回内容。新增测试包含真实私有存储的跨租户和撤回拒绝，以及读取过程中失效的失败路径。

另设两个与检索质量分开的诊断：

- **19 个已知切点回放**：在每个旧切点冻结左右相邻的两个原文词，给定含左词的来源命中，再看返回内容能否同时保留左右词。它是已知失败的机械回归，使用已知来源命中，不是额外 19 道真实检索题或独立黄金集。
- **超长句回放**：检查所有超过 500 字符的原句在分片前后能否还原。当前真实语料此类样本很少；额外的合成测试覆盖多分片、重叠、单位和条件，但不计入真实检索成绩。

## 结果

**本轮优先候选：完整句子组合，500 字符为软目标，表格仍每行一块。** 它与超长句关联方案并列最高，但不需要额外父子引用和上下文扩展；该选择来自已观察的小语料对照，没有自动修改业务策略。

2026-09-17 实测结果如下。完整证据包的分母为 56；切点列是独立的 19 次已知来源回放，不能与检索准确率合并。

| 方案 | 块数 | 混合 Recall@5 | 混合 MRR@5 | 预算内完整证据包 | 切点回放：返回左右词 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 当前 1,000 字符 | 568 | 91.07% | 0.7452 | 78.57%（44/56） | 19/19 |
| 上轮 500 字符 | 751 | 92.86% | 0.7655 | 85.71%（48/56） | 0/19 |
| **完整句子组合，软目标 500** | **759** | **92.86%** | **0.7887** | **89.29%（50/56）** | **19/19** |
| 完整句子 + 超长句关联还原 | 760 | 92.86% | 0.7887 | 89.29%（50/56） | 19/19 |
| 旧 500 索引 + 补齐原句 | 751 | 92.86% | 0.7655 | 85.71%（48/56） | 19/19 |
| 旧 500 索引 + 补齐原段落 | 751 | 92.86% | 0.7655 | 82.14%（46/56） | 16/19 |
| 句子/超长句索引 + 补齐原段落 | 760 | 92.86% | 0.7887 | 85.71%（48/56） | 17/19 |

相对上轮 500 字符方案，完整句子方案新增成功 **2 题、未损失原成功题**，均来自咖啡渣 PLA 研究的英文题：薄膜厚度范围与显微镜型号。两道题在旧方案中的标注证据未进入最终预算包，新方案保留了证据。它们来自同一文档家族，不能把这两题当作独立泛化证明。相对当前业务 1,000 字符方案，完整证据包增加 6/56，即 10.71 个百分点。

完整句子方案的正文题为 41/46、表格题为 9/10；中文 24/28、英文 26/28，中文相对上轮没有提高。原开发题为 25/30，已观察的原冻结有出处题为 25/26。完整源文本非空白覆盖、表格结构保持均通过。

三路检索的预算内完整证据包如下：

| 方案 | 关键词 | E5 向量 | 混合 |
| --- | ---: | ---: | ---: |
| 当前 1,000 | 57.14% | 51.79% | 78.57% |
| 旧 500 | 64.29% | 58.93% | 85.71% |
| 完整句子 500 | 64.29% | 58.93% | 89.29% |
| 超长句关联还原 | 64.29% | 58.93% | 89.29% |
| 旧 500 + 原句 | 64.29% | 58.93% | 85.71% |
| 旧 500 + 原段落 | 53.57% | 58.93% | 82.14% |
| 关联索引 + 原段落 | 53.57% | 58.93% | 85.71% |

**边界修复和检索提高是两项不同结果。** 旧索引补齐原句能修复全部 19 个已知切点，但这 64 题的预算内分数没有提高。因此它可以是保留旧索引时的修复方向，不能宣称比重建句子索引更优。补齐原段落在 3 个切点（组合方案 2 个）因正文与来源链超预算而被整体跳过；这是明确缺失，不是截断后冒充完整。

**超长句关联的独立收益尚未证明。** 真实语料中只有一个超过 500 字符的句子，长度 563，来自 PMC10670670；分成了两个有同一父范围的子块。回放中关联方案成功还原，证据包为 608 token；直接保留该完整句子只需 449 token。64 道查询的所有三条路径均没有实际返回该超长句的扩展包。因此关联方案的 89.29% 不能归功于这项机制。合成测试证明分片、父范围、重叠、单位条件和还原边界能够工作，不能代替真实长句的质量测量。

**更多上下文不一定更好。** 在旧 500 索引上补齐原段落，相对旧 500 原块新增 1 题成功、损失 3 题。显微镜型号题得到恢复，但 REC 保护气体、GP 透气率、PLA-C3 OTR 的部分问题失去预算内证据。组合方案新增 2 题、损失 2 题，未优于简单的完整句子方案。

完整句子方案仍失败的 6 题为 `rec-gas-zh`、`rec-store-en`、`alt-pack-zh`、`alt-store-zh/en`、`green-ldpe-thick-zh`。其失败要继续区分排序、原文锚点标注局限与打包预算，不应继续缩小 chunk 直到这组已见问题全对。七组原始无答案识别仍全部为 2/8；生产信息缺失时的相关召回问题没有因切分而解决。

## 用量和耗时

| 索引 | 块数 | 实际建库编码 token | 模型 forward passes |

| 当前 1,000 | 568 | 159,829 | 592 |

| 完整句子 500 | 759 | 174,056 | 783 |
| 句子 + 长句关联 | 760 | 174,167 | 784 |

完整句子索引相对旧 500 只增加 8 块（约 1.1%）、603 编码 token（约 0.35%）。扩展方案复用同一个索引，不重复计算其建库开销。每个索引的每条向量/混合查询路径实际编码均为 1,655 token；四个索引合计 13,240 查询编码 token，关键词路径为 0，不把共享结果的七组输出重复计费。

| 旧 500 | 866.5 | 52.71 / 56.89 |
| 完整句子 500 | 874.6 | 54.48 / 61.93 |

全部结果均未超过 1,024 token。完整句子方案的纯检索 P50/P95 为 39.27/45.72 ms，上表额外计入来源重读、扩展和 tokenizer 打包；不能直接与 v1 只计检索的延迟相减。宿主 Apple M5、10 核、24 GiB、Darwin 25.6.0，串行并发 1、ONNX 线程 2/1，固定顺序单次运行、负载未隔离，不以数毫秒差异选优或声称生产性能。

逐题配对、语言/正文/表格切片、回放失败位置和用量汇总见 [分析记录](../evidence/knowledge-sentence-analysis-v2.json)。当分数并列时，这轮选择实现更简单的完整句子方案作为后续业务接入候选。

本次资料仍都是研究论文，供应商 TDS、独立人审、新冻结文档家族及真实用户验收尚未获得。没有运行答案生成、LLM Judge 或工业结论验证；不能把来源覆盖解释为生产参数正确率。公开研究也不能直接确认订单尺寸、保质期、认证或价格。

## 复现与交付

```bash
npm run eval:knowledge-sentence -- --prepare
npm run eval:knowledge-sentence
npx vitest run server/knowledge/sentenceEval.test.ts
npx tsc -p tsconfig.server.json
```

协议、模型与代码哈希、候选和规则在 [`data/knowledge/chunking-v2/protocol.json`](../../data/knowledge/chunking-v2/protocol.json)。原问题标签和 19 个探针在同目录的 `cases.json`、`boundary-probes.json`。协议先冻结再跑检索；源码或参数变化会拒绝沿用同名实验。

索引与原始清单在 `.blackx-data/knowledge-sentence/<protocol-hash-prefix>/<index>/`，`source-map.json` 保留块到原文位置及超长句父范围。索引复用既有不可变版本、内容哈希、事务和恢复能力；完整文档可复用，中断中的文档重算，不发布半个文档。每个索引的查询及关联候选全部完成后原子保存结果。默认重跑复用完成结果，不重新测延迟；独立复测时先另存报告并移走整个实验目录。

最终完整结果在 [`knowledge-sentence-v2.json`](../evidence/knowledge-sentence-v2.json)，包含索引用量、原始命中、实际返回范围、补齐引用、预算跳过、单独的检索/上下文处理耗时和诊断回放。业务 Agent 的知识库继续位于 `.blackx-data/knowledge/knowledge.sqlite`。

新增 7 项回归通过，全仓 63 个测试文件、359 项通过、20 项既有环境跳过，构建及独立服务端类型检查通过。再次运行成功复用四个索引的完成结果；v1 的题目、标签和冻结源码哈希仍匹配。详细记录见 [验证清单](../evidence/knowledge-sentence-verification-v2.json)。本轮未替换业务分块，也未进行新策略的浏览器/真实员工验收；进入业务前须保留旧证据版本并验证旧引用仍可读。
