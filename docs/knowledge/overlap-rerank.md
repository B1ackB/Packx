# Overlap 与 Top-20 重排实测，以及业务数据取舍

2026-09-18。当前采用 SQLite + 384 维本地 E5 + 精确余弦检索。原业务研究资料保持 5 篇 / 568 块；新增业务内容为 6 条供应商产品目录。研究实验另有 7 篇 / 6 家族 / 1,064 个完整句子分块，不能拿这个数量证明包装产品覆盖。按用户进一步要求，停止扩充论文，新下载的两篇仅在隔离实验库。

## 固定对照

使用 80 题，其中 64 题已经在前几轮观察过；新增 16 题为两篇独立研究的 8 对中英文问题，在本轮检索前冻结。72 题有源文位置标注，8 题为无答案或过滤问题。所有标注由 Agent 对照原文，仍需人工审核；不是专家黄金答案，也不能按 80 个独立业务任务计算统计显著性。

三个策略使用完全相同的 7 篇文档、同一 E5、同一重排模型、同一题集、同一 1024 E5-token JSON 证据预算（含引用元数据）。基础分块使用完整句子，500 字符为软目标。为了单独衡量 overlap，保持基础切点和 1,064 个块数量不变，在每块前面追加同一个原始段落的完整尾句：最多 0、32、64 E5 tokens。上一句超过限额时不添加；这不是固定长度的强制重叠，更不会重新从句子中间切断。表格行及表头、单位、脚注和条件不变。

| 完整句子 overlap 上限 | 实际增加前文的块 | 索引输入 tokens | 原混合路径完整证据 /72 | Top 20 + rerank 完整证据 /72 |
| --- | ---: | ---: | ---: | ---: |
| 0 | 0 | 237,273 | 59（81.94%） | **60（83.33%）** |
| 32 tokens | 149 | 240,845 | 57（79.17%） | 58（80.56%） |
| 64 tokens | 334 | 252,035 | 54（75.00%） | 59（81.94%） |

**本轮选择不加 overlap。** 32/64 上限分别增加 3,572/14,762 个索引输入 token，没有增加完整证据覆盖。部分命中变大后无法装入固定证据预算，也存在相邻块重复占用上下文的现象。该结论只覆盖这个完整句子前缀策略、题集和预算；不是“任何 overlap 都无效”。原来的 token-window 分块对照仍保留在 V1，不与本轮混为同一个实验。

## Rerank 的增益与代价

上游 [多语言 Cross Encoder](https://huggingface.co/cross-encoder/mmarco-mMiniLMv2-L12-H384-v1/tree/1427fd652930e4ba29e8149678df786c240d8825)，Apache-2.0，固定提交 `1427fd652930e4ba29e8149678df786c240d8825`，qint8_arm64 ONNX，CPU，问题与片段成对输入，按原始 logit 排序。复用 Transformers.js 4.3.0，不调用生成模型，不新增网络服务。Embedding 与 reranker 是不同用途的模型，重排模型不生成向量索引空间。

无 overlap 时：

| 检索路径 | Recall@5 | MRR@5 | 1024-token 完整证据 | 新家族 /16 | 检索、重排与打包 P50 / P95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 关键词/精确字段 | 76.39% | 0.6301 | 46/72 | 9/16 | 48.1 / 57.0 ms |
| 向量 | 73.61% | 0.5211 | 40/72 | 7/16 | 52.1 / 60.9 ms |
| 现有混合（含表格多样化） | 88.89% | 0.7315 | 59/72 | 9/16 | 64.8 / 76.1 ms |
| 原始混合 Top 20，不重排 | 84.72% | 0.7118 | 56/72 | 9/16 | 63.6 / 97.0 ms |
| 同一 Top 20，本地重排 | 87.50% | 0.7660 | 60/72 | 12/16 | 511.6 / 1,002.5 ms |

“原始 Top 20”与“现有混合”不同：前者直接取融合顺序，后者已有表格多样化。只对相同 Top 20 比较，重排有 7 题改善、3 题退步，净增 4/72，约 5.56 个百分点；对已有混合路径则 5 题改善、4 题退步，净增 **1/72**，Recall@5 还略降。不能只展示看起来更大的提升。

重排单独耗时 P50 445.5 ms / P95 939.3 ms；无 overlap 的 80 题累计 403,694 个重排输入 token、1,711 次窗口推理。这里包括超长表格分窗，不等同于 1,711 次外部请求。没有付费 API 调用；本地计算资源成本没有货币化，生成耗时、成本和生成正确性为未测。Rerank 并没有修复无答案判断：原始空结果识别仍是 2/8。分数高仍可能是无支持内容，业务依赖字段缺口、引用和人工确认。

失败分析举例：重排改善了 `alt-pack-zh`、`poly-table-zh`、`instant-table-en`，但使 `pla-oxygen-conditions-zh`、`pla-flow-zh`、`pla-water-method-zh` 的完整证据预算结果退步。对于条件密集的工业参数，泛用相关性模型可能把概述排到方法段落前面，需核对实际源文；本轮没有再用这些失败调新的重排参数。

性能环境：Apple M5，10 核，24 GiB，Darwin 25.6.0，Node 24.14.0 / ICU 78.2，ONNX intra/inter threads 2/1，并发 1。本机单次固定顺序测量，共享工作站，不是生产负载或多次重复的统计结果。新家族只两组，不能据此推断供应商 TDS 的质量收益。

## 真正接入 Agent 的部分

`PACKX_KNOWLEDGE_RERANKER=local-mmarco` 让 API 和 `knowledge_search` 在混合模式走 RRF Top 20 → 本地重排 → 最多 8 条证据。关键词、向量路径保留作对照。配置缺失时保留原混合路径；配置已启用但模型失败时显式 unavailable。检索/重排均不确认 Fact。用户选择、版本、Approval 和失效复核沿用已有流程。

业务产品目录采用独立 `packaging_find_products`：先按咖啡形态与产品名称过滤，再从已索引的目录版本读取，**不查论文**。当前只有 6 条元数据，使用确定性字段匹配；无需对 6 条目录强行运行 reranker。目录没有层厚、OTR、报价等权威参数，不填猜测值。研究与产品目录分开使用，详见 [产品数据说明](product-database.md)。

实验的完整句子分块尚未替换原业务研究快照；不会为了优化自动重写原文版本、参数标注或已选来源。短产品目录每条一块，没有 overlap。用户授权的型号 TDS 到位后，应按段落/表格结构建块，先冻结实际业务问题，再评测分块和重排。

npm run knowledge:reranker
npm run eval:knowledge-overlap
npm run eval:knowledge-replay -- v2
npm run eval:knowledge-replay -- v1
