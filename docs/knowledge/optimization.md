## 实验设计与可复现边界

- 沿用原来的 64 题：56 道有暂定出处的中英文问题、6 道无依据生产问题、2 道型号/日期过滤问题。有答案题每题一个严格出处锚点，Recall@5 分母为 56；无答案识别单独按 8 题计算。
- 先在 30 道 development 题上运行 5 种消融，再运行完整 64 题回归。旧 frozen 部分已被观察，**完整集不是独立盲测**。标签为 Agent 对照原文、待专家审核，未用模型答案作为黄金答案，也没有重新标注来抬高分数。
- 同一 E5 权重、q8、384 维、CPU 两线程、同一索引、K=5、并发 1；每次向量/混合搜索仍只做一次查询 embedding。追加词语增加 token，不能称同 token 成本实验。无生成调用、LLM Judge、重排模型、在线查询改写或缓存命中。
- 词表只含通用包装术语，不含文档 ID、目标数值或答案；没有按每题预期文档施加过滤。Domain 提供词表/字段检查，Enterprise/Adapter 实现通用评分与权限。Core 和业务库未改变。
- 开发报告保存策略、排序、Store 源码哈希；完整回归运行前检查哈希一致，并保存开发报告哈希。候选修复“同一章节中不同表应分别分组”的导入兼容问题后，重跑了同样的开发与回归；分数未变。未按完整集剩余错误继续调参。

## 为什么改这些地方

原关键词按词项等权重叠打分，英文常用词、重复标题和表说明容易淹没短小的参数或方法段落；原双语别名仅供词项向量基线使用，没有进入真实 E5 查询。大表格逐行索引虽保留了出处，却会使多条相似行占满 K。

新策略 `packaging-fields.v1` 做三件事：追加确定性的中英文术语；在当前权限与适用性过滤后的语料中计算字段 IDF，让正文/表头/单元格比标题和重复说明更重要；减少同一版本同一表格的重复占位，并为明确点名的样品保留多行。表格原文没有删除，不同版本没有合并。关键词路径不是 BM25。

纯向量路径跳过无用的关键词评分。同分结果按文档身份、资料版本和源块序号排序，避免内容哈希改变无关排序。实现及回退见 [ADR-0020](../adr/0020-explainable-packaging-retrieval-policy.md)。

## 开发集消融：先证明各项贡献

下表均为同 30 题的混合路径，不用完整集选择参数。

| 策略 | Recall@5 | MRR |
| --- | ---: | ---: |
| 原词项重叠 + E5 + RRF | 46.67% | 0.3817 |
| 仅加双语术语 | 56.67% | 0.4650 |
| 仅改字段 IDF | 60.00% | 0.5778 |
| 双语 + 字段 IDF | 73.33% | 0.6667 |
| 双语 + 字段 IDF + 表格预算 | 83.33% | 0.7056 |

因此选择最后一项作为当前本地候选。每种策略的 keyword/vector/hybrid 结果均在 JSON 中，不只保存获胜项。

## 完整 64 题回归

| 路径 | 原 Recall@5 → 优化后 | 原 MRR → 优化后 | 原 P50/P95 → 优化后 P50/P95（ms） |
| --- | ---: | ---: | ---: |
| 关键词 | 33.93% → 75.00% | 0.2768 → 0.5786 | 13.61 / 18.40 → 19.97 / 20.73 |
| 本地 E5 向量 | 58.93% → 80.36% | 0.4670 → 0.5509 | 23.94 / 24.93 → 23.05 / 25.41 |
| 混合 RRF | 46.43% → 91.07% | 0.3830 → 0.7452 | 23.02 / 24.30 → 30.96 / 34.37 |

混合路径命中 51/56 个暂定锚点，相对旧混合路径新增命中 25 题，未丢失原先命中的题；中文 25.00% → 92.86%，英文 67.86% → 89.29%。向量路径英文仍为 85.71%，不能将中文提升概括成所有语言都提升。

完整集每条向量/混合路径的查询输入从 1,401 增至 1,655 tokens，增加 254（18.1%），调用次数仍为 64。关键词路径增加了计算字段权重的 CPU 工作，混合 P95 也上升；本轮优化目标是召回，没有声称全面降低延迟。

记录时间 `2026-09-17T08:40:55.755Z`，Apple M5 / 10 核 / 24 GiB / Darwin 25.6.0 / Node v24.14.0；固定模型 `Xenova/multilingual-e5-small@761b726dd34fb83930e26aab4e9ac3899aa1fa78`，模型空间及文件哈希见 [模型锁](../evidence/knowledge-model-lock.json)。耗时含本地查询编码、可见性检查、扫描评分和审计，不含模型加载、HTTP、UI 和生成。串行单次运行、宿主负载未隔离，数毫秒差异不构成性能优势证明，也不是生产 P95。

## 细分提问：有效，但并非处处有效

保持返回预算最多 8 个片段：大问题 1 次 × K8；小问题 4 次 × K2。以下为优化后结果；四问的查询量和成本高于一问，不是同费用比较。

| 任务 | 路径 | 大问题证据覆盖 | 四问覆盖 |
| --- | --- | ---: | ---: |
| REC 结构/厚度/样品/储存 | 关键词 | 25% | 50% |
| REC | 向量 | 0% | 50% |
| REC | 混合 | 25% | 50% |
| 银皮 PLA 参数/氧气条件/水蒸气方法/压差 | 关键词 | 0% | 100% |
| 银皮 PLA | 向量 | 25% | 25% |
| 银皮 PLA | 混合 | 0% | 100% |

例如 PLA 四问分别限定“PLA-C3 的表格原值”“氧气测试温湿度/流量”“水蒸气测试标准”“WVP 公式的压差”。混合的查询输入为 25 → 135 tokens、调用 1 → 4；REC 为 21 → 102 tokens。拆问帮助字段型问题，但仍不能解决所有 REC 储存段排序或纯向量跨语言失配。

## 证据缺口和业务状态

三条路径原始无答案识别仍为 **2/8 = 25%**。型号不存在/早于出版日期会返回空结果；另外 6 道生产问题仍召回相关研究片段。没有更改阈值或把业务拒答重新算成检索成功。

新增字段检查使 6/6 道生产问题提示对应缺失字段：尺寸、报价、认证、保质期、热封温度、阀开启压力。相同规则也接受具有匹配原始参数的合成正例、拒绝不同样品的记录、对缺单位/测试条件/多样品比较要求复核，避免只靠“一律拒绝”通过负例。

这是当前返回片段中结构化记录的存在性检查，**不是全文无答案检测、语义蕴含或生成正确率**。在 56 道有暂定出处的问题中，keyword/vector/hybrid 分别有 6/1/0 道仍被提示结构化证据不足；原始记录可用分别为 14/18/19 道，其余需要复核。没有把 `conclusionAllowed=false` 计为安全准确率；自由文本支持性、引用蕴含准确率和生成质量仍未评测。

UI 同时显示命中与缺口、逐字段追问；Tool 返回相同检查，裁剪长结果后重算引用集合。`knowledge_search` 进入真实 Runtime 与 ContextEngine 的离线业务演示会查询 500 克袋尺寸，校验缺口抵达模型上下文，再生成需求单。脚本 Provider 故意返回无依据尺寸，由 Worker 拒绝；来源厚度仍为 unverified，确认与 Approval 继续分开。研究参数仍不能一键转为订单生产参数。

普通搜索保留不需要真实模型的关键词入口。导入研究全文且启用本地模型时，界面选用此次实验较好的混合路径。没有默认扩大模型调用次数或自动拆问调用。

## 剩余失败与标注复核

优化后混合的 5 道未命中锚点题保留在报告中：

- `rec-store-en`：预期方法段 `PMC11243642:39`，实际首条 `:24` 和后续 `:17` 也出现相同储存时长与温度，但讲的是实验结果。严格锚点评分仍记失败；需要人审核定可替代出处，不能在这轮偷偷放宽标注。
- `alt-pack-zh`：返回咖啡胶囊的感官结果表，未找到每包 10 粒所在的 `PMC10931445:16`。检索到胶囊相关表不支持装量答案。
- `alt-store-zh`、`alt-store-en`：储存/实验等词把结果段排在方法段 `:21` 前，原始实验设计未进前五。需要新开发样本验证章节倾向，不能直接硬编码“方法段优先”。
- `scg-microscope-en`：返回厚度区间和泛称 optical microscope 的 `PMC10670670:64`，未命中具体 Olympus BX51 型号的 `:31`。主题相关不足以回答具体仪器。

当前只有 5 个文档、4 个文档家族，开发词表也可能贴合这些研究；中英文同一出处问题彼此相关。下一道外部质量门槛是供应商授权资料、独立人审标签和新冻结文档家族，不是继续在这 64 题上调到满分。

## 验证、复现和回退

本轮新增 14 项离线回归，覆盖字段权重、同分稳定性、多行比较、不同版本/同章节不同表、有限字段支持、私有资料不影响可见排序/分数/引用、异步撤回和 Tool 裁剪后引用一致。业务集成继续验证 Plan、确认、Approval 和来源失效。

```bash
# 已有固定依赖；首次准备本地模型需要显式联网下载，没有付费 API。
npm run knowledge:model
# 校验仓库中的授权快照并建立可复用真实索引；离线本地模型运行。
npm run eval:knowledge-real
npm run eval:knowledge-optimize
npm run eval:knowledge-optimize -- --all
npm run test -- server/knowledge server/manufacturing/knowledgeApi.test.ts
npm run demo:knowledge
npm run check
PACKX_KNOWLEDGE_MODEL=local-e5 npm run dev
```

不需要再次下载研究全文，原始字节和取得记录已经保存在仓库。优化脚本复用 `.blackx-data/knowledge-real-eval/<corpus-hash-prefix>` 中的索引；不存在时先运行真实基线。模型缓存只从固定本地路径加载，未准备时报错，不偷偷发起在线模型调用。重跑实验会重写相应 JSON，请先保存需要比较的报告。

本轮完整检查为 60 个测试文件、292 通过、20 个既有环境跳过，类型和前端构建通过；最终补充的 Runtime 缺口读取通过 3 项集成测试与演示。66 题合成基线完成复跑，召回、MRR 和无答案指标与历史报告一致。具体命令和源码/报告哈希见 [本轮验证记录](../evidence/knowledge-optimization-verification.json)。本轮没有重新做浏览器操作验收。

无需数据迁移或重建 embedding 即可切换策略；从 Host 移除可选策略注入可回退旧排序，原文、选择版本、Fact 和审批不变。新检索策略/审计版本、模型版本和语料版本各自保留；未来任何缓存须包含这些版本及完整权限范围。本次无新依赖。

## 可用于简历和面试的表述

> 基于 5 篇开放许可包装研究全文搭建可追溯检索实验，在固定本地 E5、568 个片段及 64 道待人审中英文问题上进行消融；通过双语术语、字段 IDF 与表格结果预算，将已观察回归集的混合 Recall@5 从 46.4% 提高到 91.1%，同时记录额外查询输入、延迟与失败案例。将证据缺口、权限隔离及引用一致性接入 Tool/ContextEngine、Plan 和版本化需求单；维持人工事实确认与审批边界。

面试应主动说明：这是个人本地原型；64 题不再是独立盲测，指标衡量锚点检索，不是工业答案正确率；6 道无依据生产问题仍有相关召回，因此候选证据必须继续经过字段复核、适用性检查和人工确认。真实用户、业务收益、供应商覆盖、专家精度、生产并发、生成成本均不填写虚构数字。
