## 三路固定基线

样本为 **7 份合成文档版本、14 个块**，其中 1 份过期资料不可查询。66 题分为 development 22、frozen_synthetic 44；同一文档家族与版本不得跨分组。题型包含型号、双语术语、参数/条件、比较、冲突、无答案、过期、地区日期和越权。答案来自显式编写的合成断言，**不是人工审核的真实工业黄金标签**；另列 8 条真实来源发现问题，未审核，未参与打分。不存在模型生成答案充当真值的步骤。

四个产品家族的模板相近，所以这些分组只能约束版本泄漏，不能证明真实语义泛化；今后的真实冻结集必须由独立文档和专家标注建立。修改合成题目、别名或语料时需保留报告中的 caseHash、corpusHash 和模型签名，不能将不同版本的分数直接比较。

硬件：Apple M5，10 核，24 GiB，Darwin 25.6.0，Node v24.14.0。检索并发为 1、K=5；同语料、同题集、固定 256 维 `lexical-hash-v1` 空间，三路顺序运行，不用重排或查询改写。向量为确定性词项特征余弦，RRF 常数 60。模型与词表完整签名见 JSON。

### 失败案例与决策

- `retrieval-*-4`：`oxygen transmission` 的语义查询没有正确覆盖 OTR，三路均有漏召回。固定别名/词项特征无法替代语义模型，需要真实语料和独立双语标签后再评估。
- `absent-3`：问“生产尺寸”会命中含“不能采购或生产”的合成文本。词项命中不表示能回答尺寸，必须保留 no-supported-answer/候选提示，并在字段写入时检查证据参数。
- `absent-2`：词项哈希向量对价格类无答案问题有误命中；RRF 合并候选使混合路径的无答案识别下降。
- 向量路径对部分厚度/条件题漏召回，且冲突版本可能遗漏。长块稀释、阈值与有限维哈希碰撞均可能影响结果；未经逐项实验，不能断言单一原因。
- 参数比较只在参数名、单位、方法、条件、适用范围均可核对时计算差值；两份演示资料的厚度可换算对比，OTR 测试条件不同则停止数值比较。未自动宣称任何真实产品性能更优。

因此保留关键词为默认，不增加重排/查询改写，也不写“混合检索效果提升”。下一轮先补真实授权语料和审核标签，再按相同预算比较真正的语义 embedding。

### 技术面试说明

**为什么没有直接上 pgvector？** 已优先评估；当前缺少实库服务、授权语料和负载证据，复用 Node 内置 SQLite 可以完整验证治理及业务边界且不改业务库。运行成本是零新增服务，代价是单 Host 同步写入与全量扫描。PG 参考 SQL 没有被包装成已实现能力，迁移需要固定版本、RLS/撤回/恢复等价性以及真实负载测试。

**为什么不让检索结果直接成为 Fact？** 资料可用只说明可以阅读，不能证明它适用于订单。检索、抽取复核、人工确认、审批是不同状态；字段绑定原始证据及不可变版本。500 克是装填要求，不能推出尺寸、厚度或保质期。

**为什么不自动解析全部 PDF？** 现有原生解析器能保留页文本，无法可靠还原所有表头、单位、脚注和测试条件。系统将其标为待复核或待 OCR，人工结构化清单才可索引；缺少真实工业表格标注时不报抽取准确率。

**一次失败如何恢复？** 原始快照先持久化，parsed 状态是可恢复检查点；队列租约控制提交权，完整索引在事务中发布，重复任务可幂等执行。昂贵调用后再检查租约、状态及许可，权限变更不会因异步间隙而被忽略。

**怎样证明价值而不夸大？** 展示命令、报告哈希、原始失败题和来源失效回归；把真实授权语料、真实 embedding、专业标签、企业试用列为后续门槛。当前证明的是可运行的数据/检索/Agent 治理工程，而非已实现业务收益。
