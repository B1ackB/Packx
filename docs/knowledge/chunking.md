# Chunking 受控对照：咖啡包装研究资料

本轮只改变分块策略，复用正在使用的 JATS 解析结果、KnowledgeStore、本地 E5、双语字段检索和 RRF 混合检索。生产解析器和 Agent 的知识库不变。实验对“分块后的证据能否被检索并装入有限上下文”负责，不测生成答案正确率。

后续的 [句子完整性与上下文补齐实验（v2）](sentence-experiment.md) 已完成，用独立协议验证完整句子分块、超长句关联和来源扩展；本页保留 v1 的原始结果与当时判断。

## 固定条件与评分

- 5 篇 CC BY 研究全文，4 个文档家族；原始 XML/PDF 的 SHA-256 继续由导入器核验。供应商 TDS 为 0，不称为市场覆盖。
- 64 道原有细分问题，含 56 道有暂定出处的问题（28 对中英文问题）和 8 道无答案/过滤问题。标签全部待人审，不能作为专家黄金答案。原“冻结集”已经观察过；本轮是探索性对照。
- `Xenova/multilingual-e5-small@761b726dd34fb83930e26aab4e9ac3899aa1fa78`，q8、384 维、CPU、Transformers 4.3.0。继续使用已有的 E5 前缀、长文本分窗平均和归一化；无模型下载或付费 API 调用。
- 相同 `packaging-fields.v1` 检索策略、候选 K=8、Top-5 诊断；三条检索路径全部运行，不只展示获胜组合。字段 IDF 不是 BM25。
- 主路径为混合检索，主指标为 **1,024 E5-token 预算内的完整证据包覆盖率**。按排名逐项加入整块，放不下则跳过；不裁剪正文或表格。预算计入来源 ID、标题、厂商/发布者、型号、版本、链接、位置、正文与表格，按整个 JSON 数组计数。
- 该 token 数是固定的上下文大小代理，不是生成模型计费 token，也不包括问题、系统提示或回答。

旧标签曾使用 chunk 编号，本轮在首次候选检索前转换为独立的**文档、原文单元与 UTF-16 字符范围**。段落按已有 JATS 的章节、锚点和段落号还原；表格按原始行保留单元格位置。所有新块另外保存 source map。评分读取 source map，不使用候选块编号作为黄金标签。

每题同时检查一个短原文锚点和一个局部上下文包：正文题取包含锚点的原句，表格题取样品名称、目标列表头和目标单元格（单位题取样品与表头）。这能区分“命中数字”与“保留局部上下文”；它没有证明整个结论、跨段测试条件或订单适用性。表格脚注和条件随块完整保留，但并未为每一道题手工标注所有必要脚注。

Recall@5 对前五块的原文范围求并集；MRR@5 要求一个块含完整锚点。主指标要求预算内块的并集覆盖证据包全部字符。另有一个明确标为事后诊断的空白敏感性检查，忽略边界空格再评分；原主指标不被覆盖。

## 七组方案

| 方案 | 正文切法 | 表格切法 |
| --- | --- | --- |
| 当前基线 | 原始段落内约 1,000 字符，优先句末 | 每行一块 |
| 小段落 | 同规则约 500 字符 | 每行一块 |
| 大段落 | 同规则约 1,500 字符 | 每行一块 |
| 256 / 0 | 同一章节内最多 256 token，按词边界，无重叠 | 每行一块 |
| 256 / 64 | 同一章节内最多 256 token，最多重叠 64 token | 每行一块 |
| 384 / 64 | 同一章节内最多 384 token，最多重叠 64 token | 每行一块 |
| 表格合并 | 与当前正文相同 | 同一表连续最多三行一块 |

Token 窗口可以跨同节的相邻段落，不跨章节/锚点；不是强行将表格压成 256 token。所有表格均保留表头、原始单位、脚注和测试条件。多行块的 `location.row` 是起始行，完整行来源在 source map 中；不将此实验定位方式直接发布给业务引用。

所有方案使用统一的 `knowledge-import.v1` 和 `EvidenceBlock` 格式。为避免原始块的参数记录被误挂到新的局部文本，实验清单统一移除 `parameters`，原文值仍在正文/表格中。当前检索编码和评分不依赖这些结构化记录；因此该对照不能声称参数抽取或生产事实核验得到改善。

## 结果与局限

具体逐题排名、原文范围、实际入选片段、跳过片段、token 用量和延迟保存在 [完整实验记录](../evidence/knowledge-chunking-v1.json)。配对增减、失败原因和空白敏感性见 [独立分析记录](../evidence/knowledge-chunking-analysis-v1.json)。本轮没有根据结果自动替换生产分块。

2026-09-17 执行了 7 × 3 × 64 = **1,344 次检索**。七组全部通过正文非空白字符完整性检查，表格来源结构由回归测试校验。下表均为混合路径，召回和证据包指标分母为 56：

| 方案 | 块数 | Recall@5 | MRR@5 | 1,024-token 完整证据包 | P50 / P95（ms） |
| --- | ---: | ---: | ---: | ---: | ---: |
| 当前 1,000 字符 / 单行 | 568 | 91.07% | 0.7452 | 78.57%（44/56） | 37.41 / 42.41 |
| **500 字符 / 单行** | **751** | **92.86%** | **0.7655** | **85.71%（48/56）** | 46.61 / 53.88 |
| 1,500 字符 / 单行 | 525 | 91.07% | 0.7521 | 82.14%（46/56） | 39.95 / 49.34 |
| 256 token / 无重叠 | 491 | 82.14% | 0.5762 | 50.00%（28/56）* | 34.27 / 39.09 |
| 256 token / 重叠 64 | 519 | 83.93% | 0.6330 | 66.07%（37/56） | 36.13 / 40.26 |
| 384 token / 重叠 64 | 445 | 87.50% | 0.6268 | 51.79%（29/56） | 32.57 / 38.14 |
| 1,000 字符 / 三行 | 389 | 92.86% | 0.6818 | 71.43%（40/56） | 28.50 / 33.13 |

\* 严格字符覆盖对三个无重叠窗口问题误罚了边界空格：`rec-opp-zh/en`、`rec-barrier-en`。事后只忽略空白重算，该方案为 **55.36%（31/56）**，其他六组不变。两个分数均保存，不能将这三题解释为实际证据正文丢失。这项检查未改变候选或原文标签，500 字符方案仍是本次观察结果最好的一组。

三条路径的预算内完整证据包覆盖如下，不把混合检索收益归因于纯向量：

| 方案 | 关键词 | E5 向量 | 混合 |
| --- | ---: | ---: | ---: |
| 当前 1,000 字符 / 单行 | 57.14% | 51.79% | 78.57% |
| 500 字符 / 单行 | 64.29% | 58.93% | 85.71% |
| 1,500 字符 / 单行 | 62.50% | 53.57% | 82.14% |
| 256 / 无重叠 | 44.64% | 30.36% | 50.00% |
| 256 / 重叠 64 | 55.36% | 42.86% | 66.07% |
| 384 / 重叠 64 | 51.79% | 37.50% | 51.79% |
| 1,000 字符 / 三行 | 60.71% | 51.79% | 71.43% |

本轮较合适的下一阶段候选是 **500 字符段落 + 单行表格**。相对当前方案，完整证据包增加 4/56，即 **7.14 个百分点**；按题配对为 4 胜、0 负、52 平，新增成功分别是 REC 的 OTR 中文题、REC 克重中文题、生咖啡装量英文题和 GP 透气率英文题。中英文预算内覆盖均为 85.71%；正文 39/46，表格 9/10。开发题为 23/30，已观察的另一组有出处题为 25/26。没有显著性或盲测泛化声明。

**追加的全文边界审计揭示了这个候选的限制。** 遍历全部正文块，500 字符方案共有 252 个段落内部切点，其中 19 个块末尾不是句末标点；1,000/1,500 字符方案对应为 0/69 和 0/26。这里是标点启发式统计，零个被标记也不保证不存在缩写误判或跨句依赖。实际例子包括把 `thiobarbituric acid reactive substances` 拆在 `thiobarbituric` 之后，以及把 `an oxygen concentration of approximatively 2%` 拆在 `of` 之后，完整位置见 [全文边界审计](../evidence/knowledge-chunking-boundary-audit.json)。当前算法优先找 `. `，但切点小于 300 字符时会退回空格，最后才按长度硬切；它不是严格的句子分块，也没有完整处理中文标点。56 道有出处的问题未覆盖这些全部边界，因此 85.71% 不能证明切分完整性。下一轮需把“完整句子优先、长度作为软目标、超长句显式处理”加入独立对照，再决定是否替换业务策略；本轮分数与冻结协议保持不变。

收益有明确成本：块数 **568 → 751（+32.2%）**，建库实际编码 token **159,829 → 173,453（+8.5%）**，模型 forward passes **592 → 775**，本机数据库文件 **6,418,432 → 8,032,256 字节**。每条向量/混合路径的查询编码均为 1,655 token，保持不变。500 字符方案的纯向量 Recall@5 仍为 80.36%，其收益主要体现为排序和预算内可用证据；不声称所有指标都提高。

在混合路径中，当前 Top-5 证据包平均为 2,104.3 token，500 字符方案为 1,819.6；都超过 1,024 的主预算。预算内实际平均分别为 842.2 和 866.5 token，全部查询不超上限。平均返回块数分别为 2.02 与 2.41。该差异解释了为什么不能仅用固定 K 宣称 Agent 已获得足够证据。

表格三行合并的建库 token 降为 111,977，但纯向量 Recall@5 从 80.36% 降至 50.00%，混合预算内完整证据包也降到 71.43%。虽然表格题预算内仍为 8/10，正文题降为 32/46：分块会改变字段 IDF、候选排序和表格多样性规则的交互，影响并不限于被改动的表格。这 10 道表格题主要查单行字段，**尚不能回答多行合并是否有利于跨行比较任务**。

与 256 无重叠方案相比，64-token 重叠改善了完整句子的召回；但 384-token 窗口平均预算内只能放入 1.52 块。现有编码器会将过长的完整输入（含标题等元数据）再按固定规则分窗池化，所以本次结论只适用于这套已固定的检索实现，不能概括为所有 embedding 模型的通用 chunk size。

仍需解决的失败有三类，逐题记录保留在分析 JSON：

| 示例 | 观察 | 下一步验证方向 |
| --- | --- | --- |
| 256 无重叠下 `rec-structure-zh/en` | 原文锚点在，但包含完整结构说明的句子被切散，预算内正文不完整；忽略空白仍失败 | 在新题上比较句子边界保护，不直接加复杂语义切分模型 |
| 500 字符下 `alt-store-zh/en`、`rec-store-en` | 所标注的方法段未进 Top-8 | 人审可替代出处，再用新冻结题验证检索改进 |
| 500 字符下 `rec-gas-zh`、`green-ldpe-thick-zh` | Top-8 含锚点，但预算筛选没有保留它 | 下一轮单独比较证据打包方式，不与分块效果混算 |

七组、三条路径的原始无答案识别均为 **2/8 = 25%**：两个过滤负例返回空结果，其余六道缺乏依据的生产问题仍有相关召回。Chunking 没有解决无依据结论问题；本轮也没有把“返回相关研究”计成拒答成功。

硬件为 Apple M5、10 核、24 GiB、Darwin 25.6.0、Node v24.14.0，串行并发 1，ONNX 线程配置 2/1。延迟包含查询编码、权限过滤、评分和审计，不包含模型加载、预算打包、HTTP、UI 或生成；宿主负载未隔离、固定顺序单次运行，不能作为生产延迟或显著性能优势。生成调用为 0，生成耗时/费用/正确率为 null，付费 API 调用为 0。本地电力成本未估算。

28 对中英文问题相互关联，且只有 4 个文档家族，不能把 56 题视为 56 份独立证据。原开发集 30 题没有表格查询，所以表格分组的结果尤其不能被写成独立验证后的泛化收益。

来源锚点标注只覆盖原先选定的位置；同一论文中可替代的正确出处未统一人审。未命中锚点不必然等于完全没有相关证据，命中锚点也不等于答案已获验证。保持原有 Fact/Artifact/Approval 流程，不从研究样品推定订单的尺寸、厚度、保质期或认证。

## 复现、存储与恢复

使用仓库锁定依赖和已准备的模型。源文件或协议发生变化时脚本拒绝继续使用同名冻结协议；新的探索应另建实验版本，不能覆盖旧标签后重算出更好分数。

```bash
# 校验/生成协议和原文位置标签；不运行 Embedding。
npm run eval:knowledge-chunking -- --prepare
# 真实本地模型：7 种分块 × 3 条路径 × 64 题。
npm run eval:knowledge-chunking
# 事后配对诊断，不改原主指标。
node --import tsx eval/knowledgeChunkingAnalysis.ts
npx vitest run server/knowledge/chunkingEval.test.ts
npx tsc -p tsconfig.server.json
```

协议、候选、指标定义、代码哈希和语料哈希在 [`data/knowledge/chunking-v1/protocol.json`](../../data/knowledge/chunking-v1/protocol.json)；不依赖 chunk 编号的标签在 [`cases.json`](../../data/knowledge/chunking-v1/cases.json)。分块实验不需要再次下载原文。

实验索引位于 `.blackx-data/knowledge-chunking/<protocol-hash-prefix>/<variant>/knowledge.sqlite`；相邻的 `raw/` 保存导入清单，`chunk-map.json` 保存完整原文映射。业务 Agent 仍读取 `.blackx-data/knowledge/knowledge.sqlite`。实验没有更改业务导入、Fact、审批、租户权限或 Agent Core。

运行按文档建立不可变索引，复用已有事务、哈希与导入幂等；中断后重跑会复用已索引文档，未完成文档重算。每个候选完成后原子写入结果文件，重跑复用它并明确打印 `resumed`。`index.documents[].reused` 区分本次重建和复用；索引事件保存实际建库 token 与模型耗时。Ctrl-C 在模型分窗之间取消，不把部分文档发布为已索引。检索阶段中断会重跑该候选的检索，不声称逐题 checkpoint。

默认重跑复用完成结果，**不是重新测延迟**。需要一次独立测量时，先将整个实验目录移到其他名称保留，再运行相同协议；另存原报告以保留历史。实验目录可以重建，不对业务库做删除或迁移。

没有新依赖，没有业务 Schema 迁移，也没有架构边界变更。本轮的新增回归检查覆盖原文锚点、表格头/单位/脚注、分块完整性、重叠推进、范围去重以及计入引用元数据的预算限制。

验证结果：新增 5 项离线回归通过；全仓 62 个测试文件、352 项通过、20 项既有环境跳过；前端构建和独立服务端 TypeScript 检查通过。此轮实验没有执行浏览器验收，也没有修改 Agent 当前生产分块。采用新切法之前，应另建版本化索引、保留旧引用，补齐新的文档家族、人审标签和多行比较任务，再验证业务工具的实际上下文打包。
