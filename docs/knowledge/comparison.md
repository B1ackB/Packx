# 来源绑定的参数比较：实验与业务闭环

2026-09-17，分支 `codex/plan-subagents`，本地未提交实现。本轮沿用 5 篇 CC BY 研究全文、568 个检索块、40 个未核验参数转录；供应商在售型号 TDS、专家黄金标签与真实企业用户仍为 0。没有新采集或付费模型调用。

本轮解决的问题是：检索到两个相关参数后，系统能否明确说明它们可否比较、缺什么依据，并把相同判断送达界面和 Agent。检索排序策略没有继续调参。此前的三路检索和拆问实验保留在 [优化报告](optimization.md)，本轮决策见 [ADR-0021](../adr/0021-source-bound-parameter-comparison.md)。

## 规则变化与细分追问

旧规则把相同字符串当成有效方法或条件，两个 `unknown`、`N/A`、空白可能通过；价格和证书数字也可能进入通用减法。新规则 `packaging-parameters.v2` 拒绝未知值、未支持的指标及单位，并要求测试方法、适用范围、原文条件相同。原值始终保留；仅精确数值厚度使用既有单位换算。不等号、区间、误差不会被截成一个数字。

阻隔指标还要求显式逐项记录的条件：OTR 为温度、相对湿度、压差、气体；WVTR/WVP 为温度及两侧湿度；空气透过性为温度、相对湿度、压差。缺项或不同项会分别列出左右来源，并追问具体测试报告及位置，例如：

- 左侧样品和右侧样品各自的测试温度及单位是什么？
- 相对湿度/两侧湿度是否相同，原文在哪里？
- 气体和压差是否明确，是否属于同一测试方法及版本？

这是 Packx 的保守自动计算规则，不是 ASTM/ISO 合规结论，也不是完整物理模型。只做受支持数值格式、单位、字段完整性及严格相等判断；尚不检查所有物理范围、不换算温度/压力、不推断等效测试方法。额外条件同样须完整且一致。无结构化条件的旧资料仍可阅读，但会要求复核。

导入的 `testConditions` 要求原值和单位出现在对应来源块；这只检查字符串存在，不证明条件与指标的语义对应关系。资料原文、程序整理和人工确认保持不同状态。

## 真实检索回归

使用原 5 篇语料和 64 题、相同本地 E5、相同索引，重新执行混合检索。每道题的命中文档、块和排序均与上一轮优化报告完全一致：Recall@5 为 **51/56 = 91.07%**，MRR 为 **0.7452**；原始无答案识别仍为 **2/8 = 25%**。比较器拒绝下结论没有被计成检索收益。旧冻结部分已被观察，这 64 题是回归集，不能重新称盲测集。

本地查询模型固定为 `Xenova/multilingual-e5-small@761b726dd34fb83930e26aab4e9ac3899aa1fa78`，q8、384 维、mean/L2、CPU 两线程；模型空间与文件哈希见 [模型锁](../evidence/knowledge-model-lock.json)。每轮 64 次查询编码、1,655 输入 tokens，生成调用为 0。真实原文、参数清单、题集与索引均未为本次修复补写测试条件。

硬件为 Apple M5、10 核、24 GiB、Darwin 25.6.0、Node v24.14.0，并发 1。记录时间 `2026-09-17T10:18:09.671Z`，混合检索 P50/P95 为 **35.42 / 40.07 ms**，包含编码、扫描、权限检查及审计，不含模型加载、HTTP、UI 或生成。宿主负载未隔离，单次毫秒差异不用于宣称性能提升或生产 SLA。没有供应商 API 账单；硬件、耗电和人工总成本未知，保留 null。

## 界面、Tool 与需求单

1. 按 [启动说明](README.md)运行 `npm run dev:fixture`，打开任务右侧「证据」，导入两份合成演示资料，搜索 `厚度 OTR`。
2. 在参数比较中明确选择左右两条参数。每项显示型号、样品、参数及版本；返回两侧原值/归一化值、方法、条件、来源页表和缺口。先比较厚度，再选择两条 OTR，观察阻断理由及细分追问。
3. 比较是只读预览。需要进入需求单时，仍须勾选证据并保存选择，通过现有 Plan 输入快照、Fact 来源链和 Artifact 版本流转。比较不会替用户选择材料、确认 Fact 或通过 Approval。

服务端 `/api/conversations/:id/knowledge/compare` 与 `packaging_compare_evidence` 使用同一实现。输入只接受两个 `evidenceId + parameterIndex` 和可选地区/日期，索引从 0 开始；不允许客户端或模型传入替代数字、单位、租户或验证状态。服务端每次复查权限、版本、地区、日期、授权和撤回状态。公共资料显式允许跨租户读取，私有资料默认拒绝。

结果受长度限制，只含所选参数与来源元数据；记录关联 ID、规则版本、索引版本、引用、过滤条件和耗时。直接引用按块 ID 查询，不为比较加载全部语料。来源类型分别显示；始终保持 `unverified` 和 `conclusionAllowed=false`。辅助冲突检查最多 64 对并提示截断，不将同一论文的不同样品自动当作版本冲突。

## 验证、复现与回退

```bash
npm run check
npm run eval:knowledge-compare
npm run eval:knowledge-compare -- --real
npm run demo:knowledge
npm run eval:product
```

普通比较评测无需模型。`--real` 要求已按 [真实实验说明](real-experiment.md)准备固定本地模型和索引；缺少时明确失败，不自动下载或调用付费服务。现有演示用脚本 Provider 验证 Tool → ContextEngine → 需求单链条，继续拒绝虚构尺寸并保留厚度为未确认。Fake Provider 不证明真实生成质量。

最终检查为 **61 个测试文件、347 通过、20 个既有环境跳过**，包含新增比较模块的 55 项测试；类型检查与前端构建通过。真实 HTTP 演示通过等价厚度、缺失阻隔条件、篡改参数、租户伪装、来源撤回等路径。电脑锁定导致本轮未完成浏览器视觉验收；HTTP、组件编译和业务测试不能替代视觉验收。命令、输出摘要、源码/报告哈希见 [验证清单](../evidence/knowledge-comparison-verification.json)。

没有新依赖或数据库迁移。通用数据字段为可选；以后补入真实条件必须产生新清单哈希和版本，不能原地修改旧证据。备份/恢复沿用既有知识层说明。若回退，应停用比较入口和 Tool，保留原文读取及已有来源链，不恢复有已知错误的旧规则作为业务放行逻辑。
