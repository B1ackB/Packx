# ADR-0026：明确确认的个人跨会话记忆与工作上下文依赖

- 状态：Accepted
- 日期：2026-09-21
- 前置：ADR-0003、ADR-0024、ADR-0025；AGENTS P0.1/P0.3、P1.2/P1.7/P1.9、P2.1/P2.6

## 背景

Session 恢复、知识库 RAG 和跨任务个人偏好是不同能力。当前用户选择先覆盖个人记忆，需要完成候选、确认、另一任务召回、修订、撤回的闭环。现有 Session 原话与工作上下文已经分离；但仅停止召回新记忆，旧助手回复、摘要和 Snapshot 仍可能带回已撤回内容。不能把全部会话导入向量库，也不能由模型将用户偏好变成订单 Fact。

## 决定

1. Enterprise 使用已有 Node SQLite 能力建立 `personal-memory.sqlite`，独立于 KnowledgeStore 的公共资料权限。记录绑定 `tenantId/workspaceId/actorId`，含来源任务/用户消息摘要、版本、确认时间、有效期及显式状态。事务内保存记录和只含标识/摘要的事件；命令 ID 去重、revision CAS，与现有 Enterprise 存储模式一致。无新服务或依赖。
2. Host 从已认证本地主体确定 owner，API 不接受任意 actor。`memory_propose` 只在普通会话且有显式记忆请求的真实用户消息时产生候选；提示词、文档、工具输出不能确认。UI 展示全文后执行明确确认，修订确认前仍使用旧有效版本。撤回清空该记录的版本正文，保留去重墓碑。Fact/审批/权限均不受记忆写入影响。
3. 初版最多 16 条确认项，每条正文 600 字符、主题 60 字符、每项 32 版、同时最多 64 个未撤回条目。这是应用策略上限，不是模型容量。按主体、来源可读性、确认和有效期确定性召回所有少量有效项，不新建个人向量库，不增加提炼模型调用。规范化同主题冲突显式拒绝；不同主题的自然语言矛盾未自动识别。
4. 普通会话、Plan/子任务及明确代本地 owner 执行的需求单 worker 复用 Enterprise Context Provider。数据标记 `user_confirmed_soft_context`，包含来源、版本与优先级边界。本轮明确请求、当前 Fact 和 Host 策略优先。所有任务仍受 ContextEngine 的完整输入预算约束，合并任务数据超过 64,000 字符或必留 Token 超限时失败，不截断记忆来伪装完整。
5. **通用状态契约增量**：`RuntimeTurnRequest.taskContext`、Session 和 ContextSnapshot 增加可选 `historyBinding`。Core 不知道“用户记忆”，只接收 Host 指定的工作历史依赖版本。依赖变化时舍弃旧模型工作历史，保留最近真实用户输入，由 Host 重新提供当前任务状态，并从执行账本恢复未决状态与必要回执；原始 transcript 不变。追加 `context.rebuilt` 事件，仅记原因和数量。
6. 压缩/模型输入/归档 Snapshot 继承该依赖，恢复和 `context_read` 拒绝不同依赖的旧 Snapshot（包括嵌套来源依赖）。配置该机制的会话，其 transcript 回读只提供用户消息；助手全文仍可在 UI 查看。个人记忆 Context Provider 不重新注入从完整 transcript 提取的旧助手工作笔记，避免绕过失效检查。显式 Artifact、用户原话、已保存业务输出不随“忘记偏好”而删除。
7. 运行中 binding 变化在下一模型/工具/保存检查点失败停止；已经生效的工具仍以账本为准，不回滚或重新执行。相同暂停 Turn 在依赖变化后拒绝恢复；需重新发起任务步骤。Plan 原有输入 revision/context 检查保留，记忆变化使旧计划不能直接确认或继续。

## 替代方案

- 只删除 MemoryStore 行：旧摘要和助手笔记会继续携带，拒绝。
- 自动摘要全部聊天并向量化：增加未授权记忆、过时版本和隐私风险，且个人偏好数量很小，拒绝。
- 把用户偏好存为 Knowledge 公共文档或 Fact：权限和权威语义不一致，拒绝。
- 给每段自然语言做完整信息血缘和选择性删除：复杂且不能可靠识别语义派生，当前以整体失效保守处理；未来需固定评测证明更精细方案有效。

## 影响、风险与迁移

数据库首次启动创建；不自动从旧聊天推断/导入个人偏好，无需删除业务数据。现有 Session/Snapshot 的字段为可选，其他未配置依赖的 Runtime 使用者维持原行为。本地主体首次启用时旧工作上下文重建，老暂停 checkpoint 可能要求重新发起；原话、事实、Artifact、执行账本均保留。缺失依赖的老 Snapshot 对启用该功能的模型回读不可用，不能模型补造丢失内容。

“忘记”意味着停止未来自动召回、清空记忆记录正文、阻止旧派生工作历史恢复；**不等于物理擦除历史对话、Artifact、WAL、备份或全磁盘副本**。当前没有生产多用户 RBAC、备份清除协调器、客户/组织共享记忆、自动经验学习。来源任务删除会使相关记忆不可用；它不会跨存储物理删除原文。损坏或不可读取存储失败关闭，不静默当作空记忆继续。

## 验证与退出条件

`server/enterprise/personalMemory.test.ts` 覆盖来源/主体隔离、幂等、CAS、确认/修订/遗忘、有效期、配额、恶意文档、重启、模型中途失效、暂停及 Plan 确认；`eval/memory.ts` 记录固定 Fake 对照、输入估算 Token 和调用数；`eval/productSmoke.ts` 验证真实 Host API 与本地认证。知识扩充独立评测，不将 RAG 收益算为记忆语义收益。

如果扩展到客户/组织或大规模个人记忆，先引入可核验主体授权和选择性召回评测。退出时先停止写入，提供用户可审阅导出及明确删除策略；不能直接移除 historyBinding 校验使旧撤回数据重新可读。没有本文测试和评测通过，不替换本保守失效策略。
