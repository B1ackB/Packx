# ADR-0042：完成任务的历史工具与文件来源复核

后续交付：本地成果 `730588e` 及外置正文完整性修复 `3834906` 已进入 [draft PR #56](https://github.com/B1ackB/Packx/pull/56)，未合并或部署；本轮接续检查见[验收记录](../evidence/completed-source-followup-2026-10-20.md)。以下保留原本地阶段的授权与范围。

日期：2026-10-20。状态：本地实现与验收；未发布。远端基线：PR #55 合并后的 main `42ff79c8a8e680ab436c170ca2d6f1aaab4e7b1d`。在 ADR-0040/0041 尚未提交的本地成果上增量实现；用户授权验证通过后将本批必要变更本地提交，不推送、创建 PR、合并、部署或调用付费模型。

## 背景、边界与完成证据

冻结 task-context 不能覆盖 worker 通过 file_read、context_read 取得的历史内容。原 Runtime 已有来源恢复校验与文件权限机制，但只在执行前、读回及等待模型时使用；完成后的读取/导入没有等待该校验。真实 Runtime、文件服务、SQLite Plan、Queue 和完成 Trace 的基线回归实际复现：文件修改后仍显示 completed。

落点是 Enterprise Plan 状态机与 Host API、Runtime Adapter、既有 Tool 来源生命周期。复用原 Agent Loop、Runtime Port、FileAgentStateStore、ContextSnapshot v2、权限、备份、引用与租户隔离；不增加 Provider、数据库、来源推断器、文件 watcher 或第二套执行循环。

## 决定

1. 将原递归来源校验原样抽为共享 `validateContextSources`，继续遍历 readDependencies、context_read、外置工具正文和 legacy 完整调用协议组。执行恢复和完成复核共用同一校验，不复制路径安全、TLS 或网络地址判断。只读 Runtime 在最终响应之后、保存完成前再次校验，避免来源在最后一轮响应时变化仍被发布。
2. Host 通过 `validateCompletedSources` 回调复核原规划者及已完成 worker。按 tenant/workspace/run、actor、stage、Session、Execution、幂等键与原结果绑定不可变完成 Trace、最终及中间 ContextSnapshot、同一任务暂停片和摘要输入存档；丢失/不匹配证据时拒绝使用，不补造或重跑模型。每次复核只读取一份作用域内 Trace 列表供收据复用，不反复扫描同一列表。最终上下文即使已移除较早读取，也复核原 Trace 实际记录的输入根，避免只检查最后一轮；不跨 Session 推断来源。原始正文继续存在 Session/快照，不复制进 Plan，也不放回模型。
3. 新只读计划（包括单节点）统一使用只读受控执行路径；`readConcurrency=2` 表示并发上限，不要求实际有两个节点。含写入/旧无标记计划仍串行，不回填或改写其历史执行语义。完成复核对现有带只读标记的历史图同样生效；旧记录能从可信工具协议组复核，缺少来源证明则停止使用。
4. Plan 读取变为异步；GET、现有 UI 轮询、完成收据对账返回及需求单导入都等待来源复核；暂停、取消和退出不受来源服务故障阻塞。复核前后重新核对当前输入和 Plan revision；等待期间产生新版本、来源失效或并发读取时，旧复核不能覆盖新状态。确认来源失效沿用一次 `plan.results_stale`，保留结果、版本、确认、尝试、用量和原有预算。恢复原文件、重启或重复读取不复活旧结果。
5. 同一回调还用于后续节点启动前和结果持久化前，防止已完成上游的来源在依赖消费前失效。异步复核后必须重读状态，再以现有 SQLite CAS 预留执行槽；否则两个就绪节点会使用旧 revision 相互冲突。取消和来源变化仍通过原代次、尝试、lease、AbortSignal 及完成后复核阻断迟到结果，不退款或冒充精确费用。
6. 校验只调用 validateContextResult，不执行工具、不生成模型响应、不重新解析文档或重新检索。文件读取继续由当前 LocalFileAccess 和版本库判断：当前文件改动不自动使允许读取的不可变备份失效；路径权限撤回仍阻断备份。完成检查只使用当前 Plan 只读白名单及 risk=read 的校验器。旧只读工具输出缺少可验证来源、工具已移除或不再被允许时，不能静默当作当前有效来源。
7. 包装参数比较和产品目录查询补上现有证据引用校验；与 knowledge_search/read/selected 共用 `KnowledgeStore.assertCurrentReferences`。核对引用、内容 hash、作用域、日期/地域过滤和撤回状态，不再次比较或检索、不调用 embedding/generation，不改变业务 Fact 权威。
8. 一次图复核最多读取 128 项输入根/依赖引用、10,000 条历史消息、200 万个序列化消息字符；外置正文也扣同一预算，原文件读取继续沿用各 Adapter 的大小限制。外置正文存档必须恰含一条 tool 消息；空存档、角色错误或多条消息视为完成证据缺失，不能静默取第一条或伪装成临时存储故障。5 秒协作式超时加单调经过时间复核；同步 I/O 不能被抢占，但超时结果不得发布。达到读取上限返回 `plan_source_review_limit`；存储故障/未知校验错误/超时返回 `plan_source_review_unavailable`，保留状态并拒绝导入；完成证明缺失返回既有 `plan_completion_evidence_missing`。明确来源变化/不可读才标记过期，不把未知存储故障伪装成撤回。
9. 需求单启动入口及所有调用方等待异步 prepareStart；等待后再检查会话 revision 和可写状态。避免导入尚未核验的结果，也防止复核期间的新对话被旧输入覆盖。HTTP JSON 结构保留，新增错误有中英文提示；界面保留历史结果并说明重试不会重新执行任务。

## 触发、限制及替代方案

“持续复核”指每次计划读取/轮询、导入及只读执行边界的持续适用性检查；不在页面关闭时每 250ms 扫描所有已完成任务或监控整台磁盘。离线期间的变化由重开后的首次读取/导入补偿。成功复核不写新的业务状态或缓存永久有效性；外部来源在校验之后仍可能变化，不能提供跨文件系统的原子事务。既有已发送/保存的数据不能追溯收回。

只记录新路径/hash、直接重跑工具、重新检索或开全局 watcher 会绕过现有来源语义或增加费用/扫描面，均不采用。历史消息仅作来源依赖遍历，模型文本不能创造 SourceTool 元数据、权限、审批或 Fact。

不重新计算负向检索结论，不保证旧的“无匹配”在语料新增后始终成立；复核已返回的来源引用和当前可读性。旧无标记串行计划不迁移，不承诺任意历史字符串可推断来源。并发上限仍为两个只读节点，单图排他 lease、最多四节点；不开放并发写入、任意代码、跨图并发、独立节点 lease、公平性或精确费用预算。

## 迁移、回退与退出条件

沿用 Plan 事件、Trace 和 Snapshot schema，无新的数据库迁移或历史重写。遵守 ADR-0040 stale 的旧二进制兼容边界；停机一致备份 Plan、Queue、Session/Trace、快照、来源、Artifact 与账本，不混跑旧版本，也不删除失效事件来伪造回退。服务内 TypeScript 启动调用改为 Promise，仓库全部调用方迁移；对外 HTTP 路径不变。未来要支持旧串行迁移、后台来源监控或更大来源集合时单独定义证据与 I/O 预算。
