# ADR-0025：有证据的执行恢复与显式降级

日期：2026-09-21。状态：接受；实现与验证结果见 [可靠性恢复](../reliability-recovery.md)。修订 ADR-0003 的未决执行契约、ADR-0012 的文件恢复边界和 ADR-0022 的重排失败策略。

## 背景

执行账本防止重复副作用，但文件已经提交、账本未提交的崩溃会永久留下 started/unknown。文件备份存在，恢复时仍需模型复制正文；重排服务不可用则整次检索失效。这些能力可以在已有 Runtime Adapter、文件审批与 KnowledgeStore 中补齐，无需引入通用 Saga 引擎、新数据库或备用付费模型。

## 决定

1. Core 不执行业务补偿，也不推断成功。执行存储增加可选的 Host 对账转换：只有有来源引用的结果才能从 started/unknown 转为 succeeded，使用原身份、输入摘要和状态做 compare-and-swap，保留原执行身份、幂等键与对账来源。普通 complete 语义保持不变。
2. Runtime Adapter 在模型调用前核对当前任务、当前 actor、允许工具中的未决记录。每片最多 32 条，每条不超过原工具超时且最多 5 秒，同时受执行片总超时约束。未配置恢复器、无证据、超时或读取失败均保留未决；不重做写操作。恢复与未解决结果进入 Trace，正文只在受控存储中。
3. 文件恢复器读取同一任务的人工审批、原输入摘要及不可变历史。已提交的 applied 回执可修复账本；executing 只有同时存在持久化计划结果、正确目录身份、匹配的磁盘后置条件和完好的备份，且未被更新的执行覆盖时，才发布恢复后的文件结果。恢复器只补内部记录，不写用户文件。单机单 Host 边界不变，不承诺识别外部进程曾写入相同字节等历史；证据只证明经批准的目标状态已经可验证。
4. 旧 executing 记录若没有原输入摘要或计划结果，仍需核查。新增字段可选，现有数据惰性兼容；不能为旧记录补造执行证据。
5. 文件补偿复用 file_write：sourceVersion 与 content 二选一，由 Host 读取同一路径、同一任务的历史内容，经哈希校验、当前版本检查和新的人工写入审批生成新版本。原审批不授权恢复，已确认 Fact、已批准交付物及跨任务资料不能由此覆盖。没有全任务自动撤销，也不会因后续模型失败撤销已成功的独立工具操作。
6. 检索对可选的向量/重排能力采用有界降级。重排失败可返回原检索候选；hybrid 的临时 embedding 故障可退回关键词。降级必须标注实际策略、原因和未知用量，重新检查权限与来源，仍然只是 candidates。显式 vector 查询、模型/索引完整性问题、用户取消、权限或来源失效不伪装成功。没有自动切模型、自动下载、额外付费服务或检索结论升级。

## 替代方案与影响

- 无条件重放 unknown：可能重复删除、写入或发布，拒绝。
- 因内容碰巧相同就认定任何历史操作成功：缺少人工审批、意图与版本绑定，拒绝。
- 自动恢复所有文件：可能覆盖用户更新且超出原审批，拒绝；提供明确的新版本补偿。
- 引入统一分布式事务或自动跨 Provider 路由：当前没有业务或评测依据，继续使用本地存储、既有 Port 与明确失败分类。

对账成功表示旧操作结果可核查，不表示当前整个任务完成，也不改变 Workflow 审批条件。恢复路径增加少量存储读取与审计；降级检索质量可能降低，必须单独标记并评测。状态读取、外部文件和账本不属于跨系统事务；对账本身中断后再次核对，不能创建新操作身份。

## 验证与退出条件

离线故障注入覆盖：外部文件提交后崩溃、账本完成前崩溃、重复恢复、无效审批、主体与任务隔离、版本冲突、备份篡改、取消、经审批的历史恢复，以及重排/embedding 失败后的权限复核和显式降级。固定对照关闭/开启恢复器，比较未决操作数、重复写入和服务可继续性；Fake 不证明真实检索质量或模型可靠性。

多 Host 写入、跨主机文件补偿和外部发布/发送操作需各自提供权威状态查询及补偿 API，再按此契约接入。在等价性未验证前保持未决，不扩大自动恢复范围。
