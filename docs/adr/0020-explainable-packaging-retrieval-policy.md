# ADR-0020：可解释查询策略、字段排序与证据缺口

- 日期：2026-09-17
- 状态：已实施；在暂定标签上选择，需独立人审集验证泛化
- 延续：ADR-0018、ADR-0019；不修改 Agent Core、模型空间、索引结构或审批状态机

## 问题与决定

固定本地 E5 的首次实验中，中文与英文召回差异较大，混合检索也低于纯向量。开发集诊断发现：中文行业词没有进入真实模型的查询准备；关键词按等权词项重叠打分，英文常用词、资料标题和大表格重复说明会稀释有效证据；同一表的多行可能占满结果预算。相关片段被召回还会使缺少生产依据的问题看似有答案。

1. 在 Enterprise 定义小型 `KnowledgeRetrievalPolicy`，通过 Host 注入 Store。Domain 提供版本化包装双语词表与字段缺口规则。Core 无行业条件分支。
2. Domain 仅追加命中的中英文术语，不注入答案、数值、文档 ID 或目标过滤条件。不使用模型改写、多查询或重排模型。原词、型号、单位和数字完整保留；已有精确型号过滤仍由调用者显式填写。
3. 通用排序先使用现有服务端权限、版本、地区和日期过滤，再仅从可见块计算 IDF。原文/表格单元与表头权重 1，章节/表说明/脚注 0.2，文档标题/型号 0.1；匹配完整型号有固定加分。采用集合词项，不称为 BM25。无长度归一化或词频饱和；语料扩大后需重新实验。
4. 保留 keyword/vector/hybrid 三条路径。Hybrid 仍为 RRF(k=60)，不改向量阈值。纯向量检索跳过无用的关键词评分。明确版本和源块序号用于同分排序，不依赖内容哈希顺序。
5. 在候选排序后，以文档版本和表格定位为组，先取每表一行和其他章节，再用延期行补足预算。问题明确点名的单词项行标识可以保留多行，例如 GP/LDPE、PLA-C3/PLA-O3。不跨版本合并，不删除原表行。没有显式点名的大表多行比较仍可能受 K 限制，必须允许指定样品和读原表。
6. 包装字段检查仅检查返回集合中的结构化参数。尺寸、报价、证书、保质期、热封温度、阀压力等缺失时返回具体追问。单位、方法、条件和多样品问题保留待复核；结果始终 `conclusionAllowed=false`。该字段不是事实状态、语义蕴含判定或全文无答案证明，不改变 Fact/Artifact/Approval 权限。
7. Tool 在裁剪结果后重算字段检查，避免引用被移除的条目。已有异步 embedding 后的权限/撤回复查保留。审计增加查询准备哈希、检索策略版本和字段检查；不记录正文或完整查询。不新增缓存。

## 评测、替代方案与风险

先对 30 道 development 题运行旧基线、仅双语、仅字段 IDF、双语+IDF、再加表格去重的消融；以同一 K、同一模型、同一索引比较。随后完整 64 题用于回归。先前 frozen 部分已被观察，报告明确不再称独立盲测。候选代码哈希绑定开发报告；回归时检查哈希未变化，保留原标签与失败案例。

独立专家黄金集是泛化结论的门槛，不阻止公开标明局限的开发实验。本决定细化 ADR-0019 最后一段的演进条件：可以先优化本地可解释基线，但供应商数据、企业部署与工业正确性仍需各自证据。

替代方案包括继续使用旧基线、直接扩大模型、重排或 LLM 查询改写。旧基线保留为实验对照；其余方案会引入成本与新变量，当前消融已有收益，因此暂不采用。没有新增依赖、数据库或付费调用。

词表可能过拟合小规模研究语料，英文停用词可能削弱某些长型号中的词项，表格预算可能损失未点名行，结构化参数缺失可能造成过度追问。完整指标同时报告语言分组、原始无答案误召回、字段覆盖不足、延迟和真实额外 token，不能把开发集收益当作生产成绩。

## 迁移、回退与退出条件

新策略不改变持久化文档与向量，已有索引无需重建。Host 与业务演示显式注入策略；旧基线评测不注入，继续可重现。撤销注入可退回旧排序；新增响应字段可选，旧消费者可继续读取。回退不能改变已选证据、业务事实或审批结论。

保留 `retrievalVersion` 和候选源码哈希，以后修改词表或排序需升版本并重新评测。如果后续加缓存，键必须同时绑定身份/权限、语料版本、索引版本、模型签名、策略版本与完整过滤条件。获得供应商资料和独立人审集后再检验迁移效果；若多表比较或语言分组回归，应在开发分支修正并重新冻结新测试集。
