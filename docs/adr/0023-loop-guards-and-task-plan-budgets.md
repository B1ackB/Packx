# ADR-0023：Host 防循环与跨版本计划预算

日期：2026-09-20；状态：接受。

## 背景

既有 Agent Loop 有迭代、工具次数和超时限制，但不会提前识别重复动作或连续工具失败。Plan 的单版本 16 次 Runtime 调用预算会在用户生成新版本后重新开始。必须在预算耗尽前阻止明显循环，并防止用重新规划绕过同一任务的总量限制。

## 决定与落点

按 P1.9 使用现有 Host Runtime Adapter 和 Hook，不修改 Agent Core Loop，不引入 Provider 依赖、Reviewer、多 Agent 或新的数据库。Hook 的观察行为保持默认；Host 显式安装终止策略，抛出带分类的不可重试错误，不修改工具输入、输出、事实或审批。

- `RuntimeLoopGuard` 在 `tool.before` 比较工具名与递归按对象键排序的参数摘要。忽略调用 ID；数组顺序保留。最近 12 个动作内，周期 1～4 的动作序列第三次重复时，在最后一个调用实际执行前停止。例如 A、A 后拦截第三个 A；A、B、A、B、A 后拦截第六个 B。
- `tool.after` 连续失败计数达到 3 时停止，同一模型批次中尚未执行的调用也不能继续。成功工具调用清零失败计数，但不清除动作历史。
- 错误码为 `repeated_actions` / `consecutive_tool_failures`，`retryable=false`。写入 `loop.guard.stopped` 事件；Conversation API 返回 422，后台 Worker 保留不可重试分类，不自动重投。
- Guard 状态在成功、暂停、失败 Trace 中持久化，仅保存固定长度摘要、计数、停止码及递增序号。按 tenant/workspace/run/session/stage/idempotencyKey 恢复，使用序号而非时钟选择最新状态；Compact 无权重写。原消息重试保留停止状态，明确的新用户消息属于新 Turn。
- Plan 按整个会话任务累计：最多 4 个版本（初始计划加最多 3 次修订）、32 次 Runtime 调用；仍保留单版本 16 次限制。规划、失败尝试、恢复均计入调用数。`generate`、`replan`、`confirm`、`resume` 与实际执行入口均有适用检查。
- Plan 连续执行失败达到 3 次后不可恢复或重新规划。规划成功不代表执行进展，不清零；只有子任务结果通过检查点才清零。取消、切换模式、修改目标文字和重启不重置总版本或总调用预算。上限适用于整个会话，包括已有完成或取消版本；继续新工作需要用户明确创建新任务。
- 沿用 `failed` 状态与事件：`plan_failure_limit`、`plan_total_budget_exceeded`、`plan_revision_limit` 明确表示停止原因。UI 展示累计额度与下一步，禁用无效操作；仅版本额度耗尽时，已有最后一版仍可在执行额度内确认和完成。

## 替代方案与权衡

只写 Prompt 无法强制停止；每步增加 LLM Reviewer 增加调用和不确定性；改 Core Loop 及扩展通用 Policy Port 不是必要条件。采用 Host Hook 的确定性策略，保留现有审批、幂等、超时、恢复与版本边界。

动作检测是保守的结构规则，不证明语义上没有进展：合理轮询同一资源也可能命中；周期超过 4 或不断改写参数的循环仍由执行片、工具次数、Plan 总量和超时兜底。当前没有业务对轮询的明确需求，因此不新增模型可控制的豁免开关。实际需要时应通过有超时和次数限制的专用轮询工具及固定 Eval 接入。

32 次是资源调用预算，不是货币费用上限。输入、输出 Token 与实际价格不同，不能据此声称精确费用。需精确费用控制时，应基于现有计量与可信模型定价新增 Host 的费用预留机制，不由模型估计或修改价格。

## 恢复、迁移与风险

既有 Trace 和 Plan 数据仍可读取。没有 Guard 的旧 Trace 从空计数开始；旧 Plan 已有版本与 calls 立即计入总预算，缺失连续失败计数从 0 开始，不猜测历史失败次数。超过新上限的旧任务保留历史，拒绝新增执行；已持久完成结果仍可恢复入账，避免把完成结果当作新调用。

Guard 在 Runtime 退出边界写入不可变 Trace。若进程在当前执行片中被强杀，当前片尚未落盘的动作历史可能丢失，恢复采用上一份 Trace；不宣称每次工具调用都具有防循环崩溃检查点。Plan 在调用 Runtime 前事务性增加 calls，强杀不能清空任务总预算；队列另有失败/租约上限。副作用仍以已有审批和工具幂等账本为准，失败不自动回滚文件。

Host 的会话互斥与 Worker 租约负责串行执行；此策略不是新增的跨主机会话锁。固定单机执行模型下，Trace 写入失败会停止，不能静默假装已保存停止状态。

退出或调整阈值需保持现有固定 Eval，补充合法重复场景与成本收益证据；不得通过模型输入、普通恢复或重新规划关闭策略。

## 验证

`npm run eval:loop-safety` 对照未安装 Guard 的 Core 与安装 Guard 的 Host，使用同固定 Provider、同任务及相同 12 次迭代预算。重复动作由 12 次工具执行降至 2 次，A/B 循环降至 5 次，连续失败降至 3 次；正常进展样例同为 5 次模型调用、4 次工具执行并完成。这只证明固定流程与停止策略，不证明真实模型任务质量。

回归覆盖参数键顺序/新调用 ID、短周期循环、同批次失败、恢复进展、跨执行片和进程重建、时钟相同、租户隔离、后台队列不可重试、跨计划版本预算、取消/模式切换绕过、连续计划失败、旧数据兼容与重新确认。
