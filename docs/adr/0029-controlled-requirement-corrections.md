# ADR-0029：受限修订、候选提取纠错与复核恢复

- 日期：2026-09-29
- 状态：接受；在线收益尚未验证
- 分层：包装 Domain 与 Enterprise 编排；复用现有 Runtime，不新增 Agent 或依赖

## 背景

v2.5 回放显示，四份 PVC 反向表述中一份因混合 `/facts` 遗漏被整份阻断；另有一份纯遗漏同样定位于 `/facts`。四份数量错误的原文均为 12000，未确认提取值却为 12500。输出截断、无效引用也与需要客户做决定的情况共用“需要补充”提示。

用户要求系统直接修订有证据支持的错误，必要时才转人工。P0.1/P0.2 继续有效：不能自动确认候选、修改已确认事实或批准交付。这里的自动纠错仅生成有来源的未确认候选；不构成上述规则的例外。

## 决定

1. 策略升级为 `packaging-requirement-evidence.v2.6`。Enterprise 按 Domain 判断逐项选择可修订问题，一次受限修订后再次复核。未进入修订范围的问题原样带入下一轮及最终 Evaluation，即使第二个 Reviewer 漏报也不得消失。范围变更仍优先要求重新确认。
2. 模型仍只能修改 title、customerGoal、assumptions，且必须对应已报告的问题。`/facts` 的 omission 可以尝试修复，但权限仅限 Host 追加引用中的完整短原文（带来源、单条不超过 2000 字符），不改变问题路径、Fact、确认状态或已有文字。没有完整可读原文、细粒度 Fact 路径和 Fact 矛盾不获得此权限。再次复核负责判断引用是否解决了要求遗漏；规则及保留问题继续约束放行。原文引用不是新的客户确认任务。
3. 未确认提取纠错在包装 Worker 的候选入库前执行，使用现有 `recordFactVersion` 和 Artifact 依赖机制。首版仅处理数量：原文中的单一整数件数须属于明确数量标签或当前产品名称；单位一致，其他有效原文中的件数必须一致。拒绝范围、估算、追加、每箱/每件、样品、变更、待批准、不同计数单位、重复候选、缺失/不可读/截断原文等情况。未列明的语法保持原有待核对流程，不猜测。
4. 当前值必须不存在，或是同源、未确认的模型候选。已确认、撤回、人工录入或人工修改的值不自动纠正。人工录入的未确认值也不能被普通模型抽取覆盖。纠正后仍为 `unverified`；原模型输出、原事实版本和纠正前后值均保留。来源不变，事实版本递增，交付物由当前 Host Facts 重建。最终仍需事实确认及具体版本交付审批。
5. `requirement-intake-corrections` 保存原文、来源版本、前后值、旧事实版本、执行身份和输入摘要。它在事实写入前持久化；恢复复用该决定，不重新推断，不增加模型调用。原模型 checkpoint 不修改。普通 Artifact 隔离、租约检查和已有事件继续适用。
6. 增加 Evaluation 决策 `recover_review` 表示复核/修订执行失败、无效输出或无进展。沿用可暂停的 `needs_input` Stage 状态，UI 根据决策显示“复核待恢复”、保留草稿和显式新执行入口；不提示客户为技术故障补资料。调用状态不明仍禁止自动重复购买。真正的业务问题继续使用 `request_input`，范围变化使用 `reconfirm_plan`。

## 替代方案与取舍

拒绝将 `every` 简单替换成 `some` 后丢弃剩余问题，也不把所有 `/facts` 指向文字字段。完整短原文引用比任意语义重定向更容易验证，但可能使草稿略长；长文仍须针对问题澄清。数量校验采用严格、保守的语法范围，当前不自动纠正任意尺寸、价格、认证或材料。

保留一个修订 Turn 和两次复核上限，不增加重试、模型路由或输出预算。尚未证明需要更复杂的修订循环。规则不能保证模型不漏检语义错误；独立复核和交付审批仍需保留。

## 验证、迁移与退出

固定旧输出用于离线权限及确定性纠错对照，历史评分、调用结果和费用档案不变；脚本补丁及 Fake 复核不能被称为新的真实模型成功率。回归覆盖混合问题保留、只报 `/facts` 的遗漏、超范围补丁、无进展、真实冲突、数量限定词/单位/来源/人工状态、纠错检查点与事实写入后的恢复、租户隔离及原输出保全。

新策略版本参与输入摘要，旧执行不能静默切换到新规则。Intake checkpoint 另绑定纠错协议，缺少该标记的旧生成结果不自动采用数量纠错，需新执行。新增审计 Artifact 与 Evaluation 字段无需存储迁移。回退时停用新策略及候选纠错，保留所有已产生版本、原文与事件，不原地恢复旧值、不重放不确定调用。推广更多字段或多轮修订前，须补充固定反例与同预算对照。
