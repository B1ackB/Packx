# ADR-0039：只读来源持续复核、报告业务依赖与零调用结果对账

日期：2026-10-19。状态：Accepted，本地实现；验收结果见[本阶段记录](../evidence/readonly-recovery-completion-2026-10-19.md)。基线 main `866379759e2113fd7948cf671e7c17a48f995660`（PR #54）。用户追加授权：补齐剩余可靠性缺口，测试通过后本地提交；未授权推送、PR、合并或部署。

## 背景

ADR-0037 的只读并发上限为 2，使用单图租约、持久任务尝试与调用前扣槽。ADR-0038 补上报告命令到活动计划的主动失效，但仍有三个可复现或可由代码确认的缺口：其他来源变化可能等到 Provider 返回才被发现；报告绑定的计划不能导入需求单；预算耗尽时 resume 会挡住本来无需模型的完成结果对账。原生 supervisor 故障 fixture 还把一秒启动时限与“输出写出后退出”的故障条件混在一起。

本阶段复用 Enterprise Layer、Runtime Adapter 和现有业务状态机，不扩展 Agent Core Loop，不引入并发写入、代码执行或新调度框架。

## 决定

1. 活动的两节点只读批次每秒复用 `dispatch` 核对冻结输入。只读 Provider 的普通生成、摘要和 token 计数等待期间，每秒复用现有 `validateContext` 与来源验证器；同一等待最多一个检查在途，结束时清理定时器。来源版本、权限、文件字节、已读工具输出与归档依赖沿用原验证逻辑。只检查实际进入上下文的读取，不把已有合法历史备份误判为活动文件。未知存储故障中断并报告原分类，不伪造撤回事件。已发送的数据不能收回，abort 不保证远端停止计费。
2. 完成的最新报告绑定计划可显式导入需求单。Host 比对当前报告绑定与冻结版本、摘要、selectionRevision、来源指纹和可用性，并读取同版本报告。保留 32,000 字符整体上限；超限拒绝。原上下文、任务图、结果、执行来源及报告摘录进入未验证来源快照。新增受保护的 `report_source` Fact 只记录 Host 依赖，不是业务字段、事实确认或生产批准；领域指令和复核策略 v2.8 同步这一边界。
3. 报告选择/撤回通知、业务 GET、字段确认、审批、导出及 worker 提交前均对账报告依赖。已有 `invalidateSource` 持久化 Artifact stale、Approval superseded、stage revision_required；保留已确认 Fact 的值与状态、历史 Artifact 和原审批记录。生成与独立 review/revision 的只读模型等待同样核对依赖。通知与业务事件不是跨库事务；崩溃后首次业务读取或 worker 检查修复窗口，不能只相信浏览器旧状态。
4. 导出检查目标 Artifact 的 `inputFactVersions.report_source` 对应历史 Fact 事件，不能用最新 Fact 替代旧依赖。导入不使用报告的新计划时，以受保护 `report:none` 来源记录显式清除当前依赖；旧版本依赖仍保留并继续阻断失效导出。这是报告→需求单→审批/导出的有限链路，不是任意业务对象的通用依赖图。
5. 新 `reconcile` 命令只接受最新、已确认、已暂停或允许恢复失败的只读并行计划。照常验证 scope、CAS、版本、工具只读白名单与当前来源；按 DAG 就绪顺序查询已保存的 Session/完成 Trace，不调用 Runtime、不派发新节点、不增加执行槽或代次。每个收据检查完成状态、任务键/Session、最终消息与不可变对话记录的一致性、工具成功、Schema、自评及证据。全有证据才完成；部分成功保留，缺失结果不能补造；不完整或不可信完成记录停止并需人工核查。来源失效、取消和新版本仍不能恢复旧确认。
6. UI 将“核对已保存结果 · 不发起模型请求”与 resume 分开。达到单版本 16 片、跨版本 32 片或失败上限时，不能借此发送新模型请求；partial 对账也不解锁新调用。计数是执行资源上限，不是精确费用上限。核对成功的子任务按既有完成检查点规则清零连续失败；没有新增结果时返回明确错误且不改状态。
7. supervisor 的退出/部分输出 fixture 先等待写出内容和 PID，再强杀进程组，并在 finally 清理。该非超时 fixture 的执行时限为 5 秒，测试总时限仍为原 5 秒；专门的 50ms/1s 超时回归和生产执行器不变。固定三次独立运行检查稳定性，随后运行完整原生套件；不靠重试到绿色掩盖失败。

## 替代方案、影响与边界

仅等待模型返回会延长陈旧运行；全局 watcher/通知总线扩大生命周期。当前每图至多两个请求，复用已有有界校验足够。把 resume 的预算检查删除会允许额外模型消费，因此单独增加只读取回执的动作。继续禁止报告导入最简单，但无法完成受控业务闭环；本次只接入已有需求单状态机，不开放通用业务依赖框架。

无新增 npm 依赖、权限、长期凭证、网络白名单或费用承诺。队列仍单机、单图租约和波次调度；没有节点独立租约、跨图并发、公平性服务。网页默认关闭，公网正向读取、真实付费模型质量/费用、真实用户收益和真实 Windows 本机行为不在本地 fixture 证明范围。

## 迁移、回退和退出条件

无数据库结构迁移，沿用追加事件和当前 Plan 状态 Schema。历史完成结果若缺少规范任务消息 ID 或对话记录，将停止供人工核查，不自动补造来源元数据或重跑。升级前按现有流程停机、一致备份 Session/Trace、计划库、报告库、事件和 Artifact。`report_source` 是旧代码不认识的新受保护业务来源；含此依赖的需求单不得交给旧版本继续审批或导出。需要回退时先停止新任务，保留快照并使用兼容版本只读核查；不得删除依赖事件、复活过期审批或重放未知操作。

若检查造成可测的读取负担，再评估有版本号的来源通知或索引；只有有真实吞吐/公平性证据时再引入节点租约或跨图调度。新增任意业务类型须单独声明依赖和失效策略，不能把此实现当作自动支持。
