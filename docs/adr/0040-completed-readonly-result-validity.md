# ADR-0040：已完成只读计划的结果过期与显式重新确认

日期：2026-10-19。状态：本地实现与验收；未发布。基线：PR #55 合并后的实际远端 main `42ff79c8a8e680ab436c170ca2d6f1aaab4e7b1d`。本阶段只授权本地开发验证，不推送、创建 PR、部署或调用付费模型。

后续本地增量：[ADR-0041](0041-frozen-plan-input-dependencies.md) 为新只读图补齐包括候选在内的冻结输入清单；本记录保留本阶段实现时的范围与旧计划兼容语义。

## 背景与完成证据

ADR-0037 至 ADR-0039 已覆盖运行中的两节点只读波次、来源主动停止、报告业务依赖和零调用收据对账。但 `dispatch` 只为活动计划构造当前输入，`read` 只返回已存状态。已完成的最新只读图在报告被撤回后仍显示 completed，浏览器保留导入入口；现有导入校验会拒绝已变化的报告，却没有让完成状态同步反映当前来源。本阶段的基线回归实际得到 completed，而不是预期的 stale。

落点为 Enterprise Layer 的 Plan 状态机、现有 Host 读取入口及 UI，不扩展 Core、Provider 或并发调度。

## 决定

1. 新增终止状态 `stale`，只用于已完成、携带 `readConcurrency=2` 的最新计划。正常完成后若对话 revision 或冻结来源依据与成功读回的当前快照不同，追加 `plan.results_stale`。使用确定性版本命令键和 SQLite CAS，重复读取/通知不重复追加。它不是执行失败：不增加连续失败、执行槽或代次，不清零既有失败，也不重写 children、taskRuns、原确认与使用量。原确认仅供历史审计。
2. 完成计划在 `GET plan`、导入需求单前的同一读取入口及报告变更通知中核对。通用 Queue sweep 继续清理过时派发，但不为所有已完成任务反复构造完整上下文。离线期间丢失通知由首次读取修复。只在成功取得不同快照时过期；未知上下文/存储错误保留原状态并报错，不伪装为来源撤回。
3. 过期是单向的：即使恢复原输入或重选原报告，也不复活旧结果。`confirm`、`resume`、`reconcile`、`cancel` 都不能改变该终止状态或启动旧节点。用户可显式 replan/generate 新版本；新版本不继承确认或节点收据，仍须独立确认后才执行。全部原有版本、片数、失败限制继续适用。
4. 需求单导入读取同一校验后的 Plan，`stale` 返回 `plan_source_stale`，不能靠绕过 UI 或重新选择报告导入旧结果。已导入需求单继续由其既有 Fact、报告版本、Artifact 和 Approval 依赖检查控制；没有增加任意业务依赖图或把 Plan 确认升级为业务审批。
5. UI 保留各节点的历史结果，明确显示输入变化及结果过期，移除导入、恢复、零调用对账和取消入口，提供重新规划。沿用现有 1.5 秒 Plan 轮询，不新增后台轮询器或新凭证。
6. 状态 Schema 对 stale 要求完整任务收据、原确认、只读并行标记和不可重试的来源变化原因。旧串行/写入计划保持原行为。Host 的 task-context.v1 比较排除阶段进度、已完成阶段、审批、pendingChanges 等下游投影，只跟踪冻结时已确认 Fact 的键及其完整记录、原有 Artifact 身份/版本、来源不可用标记，并保留报告绑定、附件、知识选择、检查点、对话输入、个人记忆及未知新字段的精确比对。新增草稿、候选及其确认不会反向成为旧计划的上游依赖。非该 Schema 的上下文仍用完整字符串比较。此检查不是所有候选 Fact 的通用依赖图，也不是任意历史工具路径的持续文件监控。

## 替代方案与边界

仅移除浏览器按钮不能修复持久状态和旧客户端；把已完成计划改成执行失败会污染连续失败/恢复语义。新增独立 Artifact、全局 watcher、节点租约或失效总线扩大了当前四节点单图场景的边界，均不采用。

调用次数仍是执行资源限制，不是精确费用上限。并发仍至多两个只读节点、单图排他租约和批次调度；不开放跨图并发、并发写入、任意代码、通用业务失效图或公网正向读取。固定 Provider 证明机制与故障路径，不证明真实模型质量或用户收益。

## 迁移、回退与退出条件

无需数据库结构迁移，但有新增持久状态。升级前停机并一致备份 plans.sqlite、Session/Trace、队列、来源及 Artifact。旧程序不认识 stale，会拒绝读取该状态，不允许混跑或删除过期事件来伪造兼容。回退先停止新任务，保留原库和兼容读取器，不复活旧确认。若需要扩大到历史全部版本、任意文件监控或任意业务对象，单独定义输入依赖及成本后再评审。
