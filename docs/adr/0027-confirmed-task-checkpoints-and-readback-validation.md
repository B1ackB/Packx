# ADR-0027：确认后的任务阶段整理与回读来源验证

- 日期：2026-09-22
- 状态：接受，第一阶段
- 分层：Enterprise 管理任务整理；Runtime Adapter 验证归档来源；Core 保持行业无关。

## 问题

ADR-0024 把可见原话与工作消息分开，但 task-context 中仍复制全部用户消息。工作消息压缩不能解决这部分增长：长对话最终触及 64,000 字符的任务上下文上限，Plan 还受 32,000 字符上限约束。静默摘要并丢弃原要求会违反 P0.1/P1.7。

独立回归同时发现 `context_read` 缺少来源验证元数据。回读内容再次进入摘要或恢复上下文后，原始来源撤回可能未被重新检查。

## 决定

1. 增加 Enterprise 的任务阶段整理 `TaskCheckpointVersion`，包含当前目标、仍有效的要求、待解决事项、进展笔记。它不创建 Fact，不确认订单参数，不证明 Stage 完成，不授予工具权限。
2. 用户在现有“个人记忆”面板内展开“整理当前任务的要求与进展”，编辑内容，先提交候选，再明确确认。第一阶段不自动生成或自动确认这些记录。
3. 候选绑定当前用户原话前缀的消息 ID、数量及摘要哈希。确认要求版本与来源完全匹配；新增消息、附件引用变化或并发修改均须重新核对。HTTP 先读完请求正文，再同步读取当前对话及 Plan 状态，防止慢请求持有旧确认来源。
4. 只有 active 版本替代更早的对话要求；后续用户输入继续原样加入 task-context。原始 transcript 与历史整理版本保留，用户原话可用 `context_read(sourceRef="transcript")` 分页回读。当前 Facts、Artifact、审批和策略继续独立读取。
5. 整理字段有界：目标 1,000 字符、约束最多 20 条且每条 400 字符、待解决事项最多 10 条且每条 400 字符、进展 1,500 字符，整体 JSON 最多 12,000 字符。未整理原话累计 16,000 字符时提示整理；此提示不是模型压缩阈值，也不授权自动丢弃内容。
6. 新版本与个人记忆依赖合成 `historyBinding`。依赖改变时重建工作消息，只保留与本轮幂等键明确对应的新用户输入及图片；旧要求不得以 objective、旧 assistant 笔记或“最后一个用户消息”重新进入上下文。旧暂停轮次拒绝直接续跑。Plan 冻结输入与当前输入不符时仍要求重新规划确认。
7. 使用 SQLite 单事务事件记录与 CAS 实现持久化、审计及命令去重，按 tenant/workspace/run 分区。第一阶段延续本机 Host 身份，不声称实现企业多用户 RBAC。删除会话后 API 不再提供该记录，数据库保留审计；物理清理是后续生命周期工作。
8. `context_read` 成功输出保存 `sourceTool`；压缩归档前、每次 token count 和模型发送前递归验证来源，共用 128 个依赖上限。兼容旧完整工具批次，以及缺失工具元数据但符合 Host 回读页格式的旧单条外置归档。来源不可用时返回不可重试的 `context_failure`，不发送该内容。
9. JSON 回读必须同时提供 `messageIndex` 与 `jsonPointer`。`offset` 在选择的数组/文本行内从零计数，缺少选择参数不再静默忽略。
10. 读取 Plan 状态、暂停、取消及退出不构建模型上下文，但仍验证会话存在与所有权。开始/确认/恢复执行继续执行完整输入校验，避免上下文过大导致无法停止和整理。

## 阈值与 Provider

Host 为已核实的官方 DeepSeek Flash 端点识别 1,000,000 Token 容量；应用输入上限仍为 100,000，默认输出预留 4,096、安全余量 8,192。压缩保持 70% 触发、45% 目标，即默认 70,000/45,000 Token；新增 `PACKX_COMPACT_TRIGGER_TOKENS` 与 `PACKX_COMPACT_TARGET_TOKENS` 配置并在启动时验证顺序和有效输入容量。目标是压缩工作集大小的目标，不保证加入摘要后精确等于该值。未知端点/模型不套用 DeepSeek 容量。

24,000 字符只是没有 Provider token counter 时的 ContextEngine 后备触发器。不得把字符、模型容量、应用输入预算、任务整理提示混为一个配置。官方依据与实测见 [实验报告](../evidence/context-phase1-report.md)。

## 验证与限制

- 固定离线用例验证长历史、反复整理、明确确认、CAS/重放、来源变更、图片、跨作用域、原话保留、恢复、旧回读兼容和 Plan 安全退出。
- HTTP fixture 覆盖候选/确认/拒绝、身份伪造、跨会话、慢请求确认期间原话变化，以及 Plan 模式阻止整理；Provider 是本地确定性实现。
- 独立真实 DeepSeek 对照仅使用合成数据，有显式网络入口、有限费用预算和调用账本，不进入常规离线检查。
- 摘要覆盖率仍可能不完整，且“覆盖消息”不是语义保真。旧单条超长无换行文本仍需要专用读取工具；本切片没有保证所有旧消息能逐字符分页。
- 人工整理可能遗漏要求，因此展示完整候选并要求用户确认；未确认时保留原规则，超限仍显式停止。需要更大规模语义评测后，才能引入自动候选生成或更激进的压缩策略。

## 替代方案、迁移与退出

不采用“提升到 1M 后持续堆叠全部原话”，因为无法消除增长、成本与关注点稀释；不采用自动摘要改写 Facts 或审批；不新增向量库或记忆 Agent。原会话无 checkpoint 时保留原行为。新数据库无记录时无需迁移旧状态；原始会话/快照没有破坏性迁移。回退时先停止执行，保留 transcript 与审计，使用原话重新构建任务并重新确认，不能把已替换的要求偷偷恢复为生效状态。
