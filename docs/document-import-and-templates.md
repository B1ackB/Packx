# 资料导入与用户交付模板

本功能服务包装售前需求整理。解析结果是有来源的观察；OCR、模板固定文字和字段映射均不能把业务 Fact 自动变为 verified。模板生成是本地新交付文件的保存，不发送客户，也不提交生产。

## 导入资料

1. 在会话的「＋ 图片 / 文件」上传资料；单文件不超过 10 MiB。
2. 展开附件的「导入正文 / OCR 预览」，点击「读取文档」。可以取消正在运行的解析。
3. PDF 显示逐页正文、文字层/OCR 方法、待处理页和识别警告。出现「继续下一批 OCR」时继续，直到没有待处理页。
4. 将附件随消息发送，再生成包装需求单。需求单保留原附件 SHA-256、解析器版本和页码来源。人工核对后才确认业务字段。
5. 本地文件也可从「文件浏览」打开 PDF、DOCX、XLSX，继续未完成的 OCR，再交给 Agent。

| 输入 | 实际读取范围 | 限制 |
| --- | --- | --- |
| PDF 文字层 | 最多 1,000 页和 1,000,000 个 Swift 字符，保留页码 | 不保留版面；超限明确标记 |
| 扫描/混合 PDF | macOS Vision 本机 OCR，中英文配置；逐页检测图像/表单内容，混合页保留文字层并附 OCR 补充 | 每批最多 12 个候选页，约 18 秒软预算，30 秒 CPU、512 MiB 进程树内存、60 秒硬超时；逐页图片最长边 2,400 px。OCR 不保证数值、手写、倾斜文字、表格关系及阅读顺序正确 |
| DOCX | 段落、表格行/列/段落标记、页眉页脚、脚注/尾注 | 不能推导 Word 实际分页；图片内文字、文本框及复杂嵌入对象不保证提取 |
| XLSX | 工作表、单元格坐标、保存的原始值与缓存公式结果 | 不计算公式，不应用日期/数值显示格式；不读取图表和嵌入图片文字 |
| UTF-8 TXT/MD/CSV/JSON | 分行正文 | CSV 作为文本读取，不推断字段类型 |
| 图片 | 原有模型附件及像素元数据能力 | 本次 OCR 专门覆盖 PDF；图片输入模型不等于确定性 OCR |
| DOC/XLS、加密或损坏文档 | 拒绝或显示不可解析 | 请先转换为支持格式或解除加密 |

Office 资料解析仍受 2,048 个 ZIP 条目、单条目 8 MB、总解压 32 MB 等既有限额约束。网络被 Seatbelt 禁止，不执行文档指令或宏。

文字层范围与 OCR 批次独立：51 页纯文字不会因 OCR 的批次限额截断，第 52 页扫描内容也会被识别。尚待处理的页具有 `ocr_pending` 警告及 `ocrNextPage`。原件不变时，完成的 OCR 批次保存在租户/工作区隔离、内容寻址的解析缓存中；重启后可继续。原件变动、撤回或权限变化时续读被拒绝。需求单来源读取拒绝已知仍有待识别页的资料，不将未完成 OCR 当作完整来源。

OCR 补充与文字层可能冲突；两者都保留，不静默替换权威值。置信度仅为 Vision 行候选分数，不能解释为业务准确率。低置信度与未识别文字有明确提示；渲染/OCR 异常不缓存为成功批次。

## 使用自己的通知/需求模板

1. 在自己的 Word/Excel 原件副本中，将需填充位置改为 `{{field_name}}`。占位符允许英文字母开头，之后为英文字母、数字或下划线，最长 64 个字符。允许自定义名字，例如 `{{customer_notice}}`。
2. 至少留出两个位置供「需求版本状态」和「需求版本」。可直接写 `{{delivery_status}}`、`{{version}}`。这样草稿不会在导出后丢失状态。
3. 在需求单预览展开「使用自己的 Word / Excel 模板」，上传 DOCX/XLSX（最多 5 MiB）。界面提供可下载示例，但用户原有模板同样可用。
4. 查看识别出的占位符、所在文件段落/单元格和周边原文，逐项选择包装需求字段。自定义占位符必须人工映射；普通空白表格、字段标签、表单控件不会被自动识别，界面会提示准备方法。
5. 点击「预览映射与填充值」，核对静态文字、字段、值、缺失项和需求状态，再勾选确认并「保存新文件并下载」。
6. 在 Word/Excel 中检查排版、分页和公式结果。原模板与不可变导出记录保存于本地 Artifact Store。相同映射与输入版本重复请求返回同一文件，不覆盖原模板。页面重载能恢复最近使用的模板；已保存记录可通过原导出编号重新读取，当前 UI 仅显示本次生成的下载项，尚无历史文件列表。

### 明确支持的模板契约

- DOCX：正文、页眉页脚、表格内的文本占位符。支持同一段落内被 Word 拆成多个文字 run 的占位符，填充值使用第一个 run 的样式。不能跨段落/单元格，不支持循环表格行、图片替换、富文本填充或表单控件。
- XLSX：文本单元格、inline strings、shared strings 及字符串值；相同共享字符串的占位符使用同一映射。填充值是带状态/单位的文本，不宣称能作为数值参与后续计算。
- 保留模板包中的静态内容、布局、样式、合并单元格和图片；模板原本设置的固定行高或狭窄单元格仍可能截断长文本。预览是字段和正文预览，不是 Office 原版面渲染器。
- 保留同一工作表内的基本算术及 `SUM`、`MIN`、`MAX`、`COUNT`、`AVERAGE`、`ROUND`、`ABS` 公式，但 Host 从不执行。删除输出的旧公式缓存值并请求 Excel 打开时全量重算。首版拒绝跨表/外部引用、命名/共享/数组公式、条件格式、数据验证等未覆盖结构。
- 拒绝宏、外部链接、OLE/嵌入对象、主动域、外部数据连接、加密文件和无效 XML。不得用此入口执行客户模板中的指令。
- 模板最多 512 个归档条目、单条目 4 MB、总解压 20 MB、128 个占位符位置；单个填充值最多 4,096 字符，生成文件最多 5 MiB。

## 版本、权限和审计

上传、预览、生成和下载都先检查当前会话权限；服务只接收已授权 scope。模板与输出使用现有不可变 Artifact Content Store 的 v1 记录。输出的 `requirement-template-export.v1` 记录包含 `delivery.template_generated` 审计事件名、actor、时间、模板 SHA-256、字段映射、完整需求版本快照、具体 Approval 引用、输出 SHA-256 与二进制内容。

生成前校验用户刚核对的 `reviewHash`，覆盖模板、映射和重新读取的需求快照。原件、Fact、来源、版本或审批状态变化后，旧确认不能复用。历史/失效需求禁止生成或重新下载办公交付文件；已在用户电脑下载的旧文件无法撤回。草稿允许导出，但必须显示 DRAFT；未确认和缺失值分别标注 UNVERIFIED/MISSING。需求版本批准不等于客户模板文件或生产文件获得批准。

## 实现与验证边界

能力落在 Host 文档 Adapter 与包装产品交付层，未扩展 Agent Core。运行时没有增加依赖；OCR 使用系统 PDFKit/CoreGraphics/Vision，模板 ZIP 使用 Node 内置 zlib/CRC32，XML 校验复用已固定版本 `fast-xml-parser` 5.11.1（MIT，见现有依赖清单）。Office 和 OCR 均在本地完成，不增加网络、付费 API 或机器安装。Apple Vision API 参考：https://developer.apple.com/documentation/vision/vnrecognizetextrequest 。

回归入口：`npm test`、`npm run build`、`npm run build:native`、`npm run test:native`、`npm run eval:product`。固定资产包含本仓库自建扫描 PDF、51 页文字 PDF、末页扫描的 52 页混合 PDF、14 页分批 OCR 文件、含继承资源的同页文字/扫描冲突 PDF、加密 PDF 及 DOCX/XLSX 示例。模板测试覆盖真实包导入/生成、拆分 run、自定义映射、缺失值、原样式、幂等重启、版本失效、租户隔离、损坏与超限、XML 实体、宏、变换命名空间的主动域及危险公式。HTTP smoke 使用本机固定 Provider，不属于真实模型质量评测。
