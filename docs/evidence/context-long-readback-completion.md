## 结论

**新 12 组全部完成，每组固定十字段均为 10/10；没有新增未知调用或工具失败。** 新版在这批样本中减少了主模型调用，原文外置后的回读也更快收尾，但整体工具次数没有减少，未知原文位置时反而增加了搜索。当前证据支持继续优化定位前的无效搜索，不支持进一步放宽每任务预算或提高压缩阈值。

三种状态来自同一个合成长任务：三轮真实压缩后的原文缺失、原文已齐、检测正文已外置。工作上下文为 82／100／86 条消息、约 15.5／17.3／13.8 万字符。每种状态各重复两次，对比 PR #20 冻结 Tool 与 PR #21 当前 Tool；第二次交换调用顺序。两侧均使用同一明确状态 Schema、问题、Host 数据、初始消息和运行预算，六对首请求消息哈希一致。完整 HTTP 请求仍因被测工具定义不同而不同。

这是长上下文中的新只读核对 Turn，不是连续执行整个业务流程或恢复未决写入。每种状态只有两次重复，不能外推生产成功率、延迟分布或单个提示改动的因果效果。旧 42 次工具轨迹使用不同评分题与持续执行状态，不能直接与本轮工具次数相减作为收益。

## 原文恢复与收尾

逐字文本、严格读取来源、按字段提取是三个不同口径。严格指标继续排除 query 摘录；事后另查每次已完成生成的真实请求是否含完整原要求和检测正文。

- 原文缺失的旧版第 1 次重复，在第 5 次请求中完整文本已经齐备，之后仍执行 7 次工具、增加 4 次主调用；严格口径到第 8 次才齐，因为此前原要求只是完整出现在查询摘录中。
- 对应新版第 1 次重复在第 3 轮同批提出 1 次检测原文读取和 5 次附加查询，第 4 次看到完整文本后直接回答。那 5 次查询发生在读取结果可见之前，不能记作“看到原文后又查”。
- 正文外置的旧版两次均在第 2 次请求看到恢复后的完整正文，仍各执行 4 次额外查询，再回答。
- 正文外置的新版第 1 次重复，直接从原检测记录用 JSON Pointer 读取证据码、温度、湿度和引用四字段，在第 2 次请求收到四个精确值后回答。它没有读取 3,679 字符的整份正文，因此 `fullReportRecoveryReads=[]`；这不代表没有恢复必要证据。第 2 次重复读取整份正文后也在下一次请求回答。

按“完整原要求＋完整检测正文＋当前 Host 均已在请求中”的逐字口径，旧版在此之后共执行 **15 次工具**，新版为 **0**。新版按四字段恢复的那一组未进入“整份正文齐备”口径，需按上述独立证据解释；不能把该指标包装成通用生产收尾保证。

所有状态合计，旧版 30 次查询中 11 次无命中，新版 28 次查询中 15 次无命中。只看原文缺失的两组，旧版为 8／17 次空查，新版为 15／25 次空查（两次分别为 9、6 次）。`query` 是字面匹配，英文词与中文原要求、`sample 4` 与 JSON 中的 `"sample":4` 等表达并不等价。

所有组的“同批同关键词来源重叠”指标均为空，只说明没有命中这条严格定义。不同关键词仍可能扫描相同来源；该指标不能用于宣称不存在重叠搜索。

## 预算、费用与阈值

每组仍为 64 次工具、32 次主调用、4 次摘要、100k 输入硬上限、70k／45k 压缩阈值和 180 秒时限。新批各组实际用时为 3.663–32.834 秒，最大输入 **56,948 Token**，没有触及压缩触发点或任务预算。放宽的只是累计实验支出上限，使重复对照可以执行；每任务预算没有提高。

因此，这次不能验证更大的压缩字符值、更多摘要调用或更高 Token 阈值更好。当前 70k／45k 与摘要默认保持原状，既有阈值结论仍以此前独立阈值实验为准。
