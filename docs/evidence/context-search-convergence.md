# 回读来源排序与核验状态评测

日期：2026-09-24。起点 `f2310928be23fe1de0af73daf3626f46e2cc89fa`（PR #20）。本轮采用既有 Runtime Tool/Adapter 落点，保持 Core、生产预算和压缩阈值不变；继承上一轮费用台账。

## 结论

新评测消除了 `supplierQualified` 布尔字段的状态歧义；小型同条件实验中，旧 Tool 与新 Tool 都得到 **10/10**，并确实将原要求和原检测记录送入后续模型请求。已通过、已不通过、完全未知三个独立控制题全部正确，待核验由两组主任务验证。

搜索现在可区分来源类型、优先列出原始对话／工具记录，并显式列出已访问来源。离线固定对照证明原检测命中从第 4 项变为第 1 项，全部 4 个匹配仍然保留；没有提升任何历史记录的事实或权限等级。

**线上工具效率尚未证明改善。** 旧 Tool 执行 4 次，新 Tool 执行 5 次，两者均为 4 次主生成。新 Tool 多出同一批次中的一次覆盖重叠搜索；该批次由模型一次提出，当时还没有收到其中任一查询结果。本轮保留这项负面结果，不能宣称减少了工具调用或解决了取得证据后的过度确认。

## 从上一轮 42 次工具轨迹得到的边界

独立审查读取[上一轮第二版报告](context-readback-optimization-v2-online.json)及其本机持久请求快照、工具 Trace：

- 42 次工具为 41 次 `context_read` 加 1 次执行账本读取，均成功；其中 37 次关键词查询、19 次空结果。只有 3 次查询含摘要命中，不能把主要问题简单归为追逐摘要。
- 第 5 次主请求已含当前 Host 数量、原要求和完整检测记录，此后又执行 29 次工具。三次宽泛查询输出合计 32,499 字符，占工具输出 80,699 字符的约 40.3%，增加了后续上下文负担。
- 中途压缩将较早的 4,560 字符检测回读正文换成 156 字符引用封套，第 30 次工具重读检测正文具有恢复用途。第 35 次工具又读原要求时，该原要求仍在输入中。
- 所有工具执行合计 821 ms；13 次主生成合计 42,970 ms，4 次摘要生成合计 8,893 ms，整段 69,575 ms。工具 I/O 不是主要耗时来源；这些局部计时不包含所有计数、序列化和框架开销。

这支持先补来源可解释性、完整扫描范围提示与明确状态 Schema。当前轨迹不能分离各类指引的因果影响，也不支持按“曾读过”强制禁止重读。上一轮完整请求快照仍依赖报告记录的本机临时状态目录；本轮小型新实验则将完整合成请求和来源直接保存在版本化报告中。

## 实现与边界

生产改动仅位于 [contextRead.ts](../../server/runtime/contextRead.ts)：

- query 命中增加 `sourceKind`：`dialogue`、`tool_result`、`summary`、`readback`、`receipt`、`task_context`、`instructions`。分类依据 Host 元数据；正文伪造的类型或“VERIFIED”字样没有影响。
- 缺少 `sourceTool` 时，只从同一来源中连续 assistant/tool batch 的调用 ID 识别回读／账本回执。遇到新的非 tool 消息即重置配对，不能跨用户消息或跨来源推断。无法配对的旧孤立工具记录保留 `tool_result`，标签不承诺精确追溯未知的历史生成方式。
- `dialogue/tool_result` 优先于派生记录，组内顺序稳定。匹配项及其精确读取位置全部保留，直接读取和再次读取仍可用；类型标签不表示可信、已核验或当前有效。
- `searchedSourceRefs` 明示访问范围。只有 `searchComplete:true` 才表示范围内完整扫描；同一关键词无需逐个子来源重复查询。命中页从 10,000 降为 8,000 字符，为最多 32 个来源引用留出封套空间，工具结果上限仍为 16,000 字符。
- 工具描述提示直接使用当前 Host 值，保留已知待核验状态，按缺失证据检索并在足够时回答。描述保持紧凑，通过原有 1,500 Token 小预算生命周期测试。

租户／Session 作用域、权限和来源生命周期校验、历史绑定、过期标记及摘要非权威边界继续由现有实现执行。32 来源／2,000,000 字符／10,000 消息扫描上限与 8 个导航根上限保持；超限仍明确不完整，尚无内部扫描或导航根续读游标。本次没有新增搜索入口、自动完成判定器、去重状态或依赖库。

## 固定的新评测版本

[context-readback.v2](../../eval/fixtures/contextReadbackV2.ts) 将评测字段改为 `qualificationStatus`：

| 状态 | 含义 |
| --- | --- |
| `pending_verification` | 明确尚未核验，或正在等待资格证据 |
| `qualified` | 明确已核验通过 |
| `not_qualified` | 明确已核验不通过 |
| `null` | 没有已知核验状态 |

待核验不能推断为核验失败。原布尔字段只存在于评测脚本，生产 Fact 已有确认状态，因此没有向 Core 添加供应商规则，也没有改写生产事实。旧 fixture、历史分数和报告继续保留。

冻结旧 Tool 来自起点提交，仅调整类型导入路径，源码及 SHA-256 在 [baseline 清单](../../eval/baselines/context-readback-v2/manifest.json)。两组使用同一份小型合成来源、Schema、系统指令、问题、Host 状态和首轮消息；首消息哈希均为 `0ca2a796b2ac3cc8c1279a9b151d7fb36a17789708e5b363c540ddf976e5ce04`。工具定义和结果格式是被测改动，完整 HTTP 输入不相同。

实验使用实际 AgentLoop、ContextEngine、RuntimeLoopGuard 和 `context_read`，固定先旧后新，各一个样本；随后执行三个无工具状态控制题。每组最多 6 次迭代、12 次工具、12,000 输入 Token、1,024 输出 Token 和 120 秒；两组都只允许 `context_read`，禁止在线摘要。这个 1,024 输出限制属于本实验，不代表生产预算；出现输出超限会按未知结果停止整轮，不临场扩额重跑。本次最高单次输出为 523 Token。

这不是完整 BlackxAgentRuntime 端到端在线测试。来源为内存合成数据，生命周期回调为空；真实运行路径的权限、撤回和恢复由现有离线 Runtime 契约／集成测试覆盖。本实验没有重跑旧 42 次工具的大上下文任务，因此不能把旧 42 与本次 4／5 次直接比较。

## 线上结果

模型仍为配置中的 `deepseek-v4-flash`，官方 Anthropic 兼容端点；本轮不修改模型配置。Provider 别名不等同于冻结模型权重。

| 指标 | 冻结旧 Tool | 新 Tool |
| --- | ---: | ---: |
| 精确答案字段 | 10/10 | 10/10 |
| 主生成次数 | 4 | 4 |
| 实际完成工具／失败 | 4／0 | 5／0 |
| 原要求首次进入实际主请求 | 第 2 次 | 第 2 次 |
| 原检测正文首次进入实际主请求 | 第 4 次 | 第 4 次 |
| 原文已齐后的新增工具 | 0 | 0 |
| 整组耗时 | 10.696 秒 | 7.879 秒 |
| 未命中／缓存输入 Token 合计 | 2,436／5,888 | 2,582／6,400 |
| 输出 Token 合计 | 946 | 516 |
| 峰价费用估算 | $0.001901328 | $0.001432200 |

新 Tool 第 2 轮同时提出 `middle-notes` 和 `latest-notes` 下的 `report-C17` 查询，存在覆盖重叠。两组均在下一轮精确读取检测原文，再直接回答。没有证据说明增加 `searchedSourceRefs` 就能阻止尚未拿到结果的同批次重叠查询；跨 batch 的提示效果也未被本小样本单独验证。

独立核对将 `toolCompletions`、返回的 `toolExecutions`、生成请求和回答逐项对齐，并用对应冻结／当前 Tool 离线重放全部 9 次读取，输出逐字一致。`originalTextDeliveredAtIterations` hook 标记本身只证明进入 `model.before`；原文送入的结论还须在对应 `completed` 请求的 `request.messages` 中验证完整精确文本。搜索片段、摘要和仅包含来源名均不计为完整原文。

三个控制题结果分别为 `qualified`、`not_qualified`、`null`，均只有要求的字段，且没有工具调用。两组主任务的待核验结果均为 `pending_verification`。这验证了这些固定表达的可区分性，尚未覆盖冲突证据、否定嵌套或长任务中的状态更新。

时间和用量是观测值。固定顺序、缓存、生成长度、网络和单次采样均可能影响它们；不能将耗时差解释为稳定加速，也不能把两组 10/10 当生产成功率。
