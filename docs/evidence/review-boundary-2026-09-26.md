# 复核位置／动作边界与脱敏错误分类

日期：2026-09-26。承接 [复核输出与失败用量专项](review-output-2026-09-26.md)。预算继续使用原 20 美元总上限，启动时已预留 12.84109872 美元；此前 37 次用量不可用记录保持原样。

## 问题与最小落点

Host 原本只允许对 `title`、`customerGoal`、`assumptions` 的 omission/unsupported 做一次受限修订。模型却可能识别出叙述遗漏，仍建议修改 `/facts`；或对 contradiction 返回 `revise`。Host 会安全转人工，但建议本身不可执行。

本轮候选只在包装 Evidence Review Policy 增加一段位置与动作说明，并提升 policyVersion；模型、默认推理模式、输出 Schema、Host 白名单、审批与事实权限均不改变。没有把错误路径自动转换为可修改路径。

另一个已确认的程序缺陷位于响应读取：`response.json().catch(() => undefined)` 会把成功 HTTP 响应的连接中断抹成 invalid_response。现在只将 JSON 语法错误转为格式错误；连接／流读取异常继续传给固定分类器。收到明确 HTTP 错误时，即使错误正文无法读取，仍保留实际 HTTP 状态。

## 错误分类与恢复边界

Host 模型遥测与在线预算账本共享固定分类：`transport_failure`、`provider_timeout`、`request_cancelled`、`provider_auth`、`rate_limited`、`provider_http_error`、`incomplete_response`，以及已有的输出上限／拒绝／格式等类别。最多沿 5 层 cause 查找白名单代码；不将原始 message、URL、任意错误 type 或密钥写入分类字段。无法识别的异常仍是 `unclassified_model_failure`，不猜测根因。

分类不会补造 usage，也不授予重试权限。离线注入验证连接未知后只发起一次生成，即使 Runtime 将错误标为 retryable；预算保留、后续调用被阻止。已保存复核结果的策略版本发生变化时，恢复拒绝覆盖旧记录且不重复购买调用。此前没有保存下来的底层异常不能靠新分类器回填。

**决定：不采用 v2.3，生产策略恢复为 v2.2，并逐字核对与前一轮源码快照相同。** 候选虽然在有效输出中遵守动作边界，但 14/16 控制检查未达到预设 16/16，且有效输出 19 次少于基线 20 次，两项采用条件失败。默认推理与 8,192 输出上限保持原值。

基线的两个控制失败都发生在 PVC 遗漏：模型发现问题，却两次定位到 `/facts`。候选两次都正确定位并通过该检查，但首次矛盾检测与首次范围扩张检测分别因截断失败。基线另有动作建议不符合 Host 边界的输出；控制检查识别对了缺陷类型，也不代表建议动作可执行。因此缺陷识别、输出可用性和动作边界必须分别报告。

“可修订输出数”只是落入 Host 既有白名单，没有执行修订，也没有形成新的业务 Artifact、审批或端到端通过结果。动作边界分母分别为 20 和 19，不能把未返回结果视为安全通过。两次重复、开发者可见样本和单次批次不支持统计显著性、生产延迟或泛化结论；本轮新增端到端业务任务数为 0。

本轮 9 个收到的截断响应均保留数字用量。这验证了上一轮失败用量保全逻辑在新在线响应中的行为；新传输分类没有遇到真实在线传输异常，验证仍来自离线故障注入，不能描述成线上网络恢复成功。
