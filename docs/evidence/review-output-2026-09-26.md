# 复核截断与失败用量：2026-09-26

本轮承接 [自动在线评测](automatic-online-2026-09-26.md)，专门检验 evidence review 的输出截断。旧报告、失败请求、评分和预算预留保持不变。所有样本都是开发用合成资料；没有企业用户或人工质量标注。

## 已确认的缺陷与修复

Anthropic-compatible Provider 收到 `max_tokens`、`refusal`、`pause_turn`、`model_context_window_exceeded` 后，会在提取 usage 前抛错。因此一次已经收到终态响应的失败调用，其用量仍被记为不可用。

现在适配器先校验并提取数值 metadata，再抛出保留原错误分类的 `AnthropicGenerationError`。错误不携带部分文本、工具调用、推理内容或签名。Host 的模型调用记录与在线预算账本保留失败 usage；任务、复核及审批仍然失败关闭。流中断、断网或尚无完整响应的请求不能凭空补出 usage。

账本新增 `failedResponse`，不将其伪装成成功的 `response`。原 `unknown` 阻止后续调用的行为保留；独立只读实验只能按冻结计划跨过已收到的 `output_limit`，不能续跑旧业务请求。所有预算预留均保留，已知用量估算不是发票，也不能覆盖旧未知费用。

## 固定实验

输入来自上一轮 pending-change 修复评测：5 个收到截断的 review 输入、1 个已完成的正常候选，以及从正常候选创建的 3 个叙述变体：遗漏禁止 PVC、允许 PVC 与原文矛盾、无依据声称取得 FSC 认证。

5 个历史失败输入只检查完整输出与 Schema/ref 合法性，不对其语义完整性评分。4 个控制候选有冻结的窄评分规则：正常候选不应报错；缺陷候选必须在相关位置识别指定问题。识别一项注入缺陷不等于其他问题全部正确或没有误报。

同模型 `deepseek-v4-flash`、同输入、同 Schema、同 8,192 输出 Token 上限；每个样本每个配置重复两次。默认/关闭推理两组交替执行。关闭推理若不能通过全部 8 次控制检查，不采用。供应商说明默认开启 `high` 推理，并支持 Anthropic 协议的 `output_config.effort=low`；见 [DeepSeek 官方思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)。接口能力不等于质量保证。

## 交付与边界

- 适配器：验证非负安全整数 usage 后保留失败 metadata，仍抛出原分类错误；部分文本、推理、签名和 Tool 不进入失败对象。
- Host：模型调用记录重启后仍能读到失败用量；失败状态不变，部分 Tool 不执行、完成消息不写入。
- Eval：已知失败 usage 计入成本与 Token 汇总；“调用仍被停止规则隔离”和“用量不可用”分别统计，不能把失败当成功。
- 回归：覆盖四种收到终态响应的失败、畸形 usage、失败用量持久化、预算超支与禁止重试、部分 Tool 禁止执行，以及错误 `/facts` 位置必须转人工而不得改写 Facts。
- 全量检查：92 个测试文件，770 项通过、21 项平台条件跳过；类型检查和构建通过。见 [校验记录](review-output-2026-09-26/verification.json)。未提交或推送。
