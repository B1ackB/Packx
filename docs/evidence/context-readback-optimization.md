# 回读优化与摘要预算对照

日期：2026-09-22。起点 `bf4bdd5`（PR #19）；第一版生产候选和负面结果保留在 `1b7aa35`，第二版增加归档导航。两个报告记录各自执行时的源码 SHA-256；本轮沿用已授权累计费用上限，不上调生产预算或压缩阈值。

## 结论与落点

原文定位和完成行为有改善，但整张答案尚未稳定全对。最终四格都完成回答，检测证据码、温度、湿度、引用四项全部正确；按原评分为 **10/10、10/10、9/10、9/10**。后两格将未完成资质核验的供应商写成 `null`，原标准要求 `false`，仍保留未通过判定。没有把“已回答”算作“全部答对”。

摘要预算确实会限制本样例的覆盖：4／8／16 次调用都没有处理到检测原文，答案均为 6/10；32 次覆盖到检测记录，答案达到 10/10，但只覆盖 129/146 条，依然不完整。32 次并非已证明的最小充分值或生产最优值。

采用的实现位于既有 Host Runtime Tool/Adapter 层：

- `context_read.query` 搜索指定来源及 Host 声明的依赖，返回原始消息位置。正文中的任意来源名不成为权限或遍历入口。
- 结果提供 `navigation.dialogue` 和 `archiveRoots`，区分用户对话与工具归档；归档根来自当前 Session，逐一重查作用域、来源权限和历史绑定。
- 明确 `messageIndex` 已选择正文，`jsonPointer` 只适用于正文中的 JSON 字段。超大文本可显式按 `characterOffset` 读取精确分片，附分片标记和续读位置；默认完整单元读取保持原语义。
- 回读结果附整批工具扣额后的剩余工具／迭代数，并提示证据足够后回答。预算、连续失败、来源撤回和权限限制仍由 Host 执行。

复用现有 `context_read`，没有新增工具权限、依赖库或 Core 策略；没有把行业字段规则写入 Core。落点符合 P1.9 的 Tool/Adapter 路径。默认仍为 64 工具／32 迭代，摘要最多 4 次，压缩阈值 70k／45k，主请求上限 100k。

## 回读：同起点四格与两版候选

使用原第三轮压缩后的检查点、同一问题、同一输出 Schema、同一 DeepSeek 别名、同一输入／输出／压缩限制。原始检测证据不在工作上下文中。每格首请求的 85 条 `messages` 与旧对应请求逐项相等；工具描述及 Schema 是本轮被测改动，完整请求 Token 数因此不同，不宣称 HTTP 字节一致。

固定顺序为 16 无提示、64 有提示、64 无提示、16 有提示，各格只采样一次。第一版结束后，根据其失败轨迹补导航，再运行完整四格；这属于两轮候选迭代，不是预注册的单变量因果实验。两版均保留，未只挑成功轨迹。

| 工具上限／来源提示 | 优化前 PR #19 | 第一版：搜索／分片／额度提示 | 第二版：再加资料导航 |
| --- | --- | --- | --- |
| 16／无 | 6/10 | 6/10 | **10/10** |
| 64／精确位置 | 10/10 | 9/10 | **10/10** |
| 64／无 | 连续工具失败，无答案 | 10/10 | **9/10** |
| 16／精确位置 | 工具超预算，无答案 | 10/10 | **9/10** |

第一版 16 无提示只在 `transcript` 反复搜索，遗漏工具归档，四项检测信息为 `null`；64 有提示的资质字段为 `null`。这促成第二版的资料导航。第一版用了 14／15／46／12 次工具，其中第三格有一次失败；没有新增摘要生成。

第二版实际轨迹如下。“工具”按当前查询的持久 Runtime Trace 中 `tool.completed` 统计，包含失败尝试，不把仅申请的工具当成已执行。最终四格工具失败均为 0。

| 工具上限／提示 | 实际工具 | 主／摘要生成 | 首次原文进入后续主请求 | 用时 | 峰价费用估算 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 16／无 | 16 | 8／0 | 第 7 次 | 35.0 秒 | $0.022437 |
| 64／精确位置 | 10 | 5／0 | 第 2 次 | 23.8 秒 | $0.006365 |
| 64／无 | 42 | 13／4 | 第 5 次 | 69.6 秒 | $0.031629 |
| 16／精确位置 | 5 | 4／0 | 第 2 次 | 18.8 秒 | $0.004747 |

64 无提示读到检测原文后仍执行较多搜索，期间再次压缩；新摘要只覆盖 35 条中的 16 条。故“找到原文后的停止效率”仍有改进空间，不能据此宣称已经解决过度查找。16 无提示恰好使用全部 16 次工具，不能据单次成功下调生产上限。

原始要求写“供应商仍未完成资质核验”，问题又要求不能确认的字段填 `null`；`supplierQualified` 的 Schema 没有区分“尚未核验”和“已确认不合格”。这使 `false` 与 `null` 存在解释歧义。独立检查确认，两条 9/10 的最后主请求都含这句原要求与检测原文，不能归因于压缩或回读漏掉该信息。当前按冻结标准保留 9/10；后续应在业务 Schema/fixture 中显式区分状态，并冻结新版本后再测，不能把“不合格”事实强加给模型，也不能事后放宽本次分数。

原始证据：[第一版](context-readback-optimization-online.json)、[第二版](context-readback-optimization-v2-online.json)、[快照／Trace／费用核对](context-readback-optimization-inspection.json)。入口：[contextContinuationVerify.ts](../../eval/contextContinuationVerify.ts)。

## 摘要：独立 4／8／16／32 档

输入为同一第一轮 146 条原始归档，检测结果在下标 71；每档新建摘要器，输入每次最多 6,000 Token、输出最多 512，总分配随调用数同步增加。原始用户要求不在这份归档中，因此从第一轮原请求快照恢复同一条 `requirements`，与同一 Host、系统指令、摘要及问题经 ContextEngine 构造评分请求。四档均只生成一次答案、没有工具或 Runtime 回读，也不重试错误答案。

| 摘要调用上限 | 总 Token 分配 | 直接覆盖／146 | 检测进入摘要 | 正确字段 | 总耗时 | 拼接摘要字符数 |
| --- | ---: | ---: | --- | ---: | ---: | ---: |
| 4 | 26,048 | 17 | 否 | 6/10 | 20.9 秒 | 4,038 |
| 8 | 52,096 | 33 | 否 | 6/10 | 31.2 秒 | 8,314 |
| 16 | 104,192 | 65 | 否 | 6/10 | 45.9 秒 | 14,011 |
| 32 | 208,384 | 129 | 是 | 10/10 | 81.6 秒 | 32,029 |

字符数包含送入评分的非权威摘要前缀；512 是单次摘要输出上限，不是最终拼接摘要的上限。评分输入依次为 1,428／2,506／3,996／7,991 Token。总耗时包含摘要、计数和一次评分答案生成，不能与上表完整 Runtime 回读直接比较效率。

独立审查用 60 条已记录的摘要响应离线重放，精确复现全部摘要与覆盖范围，再重建四个评分请求哈希。32 档的第 18 次请求 `[69,73)` 首次包含检测记录，输出确实保留 `SEAL-9Q7`、23°C、50%RH、`report-C17#sample=4` 和不得改变订单的否定约束。其余三档的四个检测字段均为未知。仍未测试 18 次等中间档，也未做重复采样。

该实验隔离了摘要额度，没有验证把自定义摘要器注入生产 Runtime 后的完整权限、生命周期、遥测和恢复链。增加额度还不能处理单条超大消息、缺失的祖先原文或跨多轮语义遗漏。因此保留生产默认 4 次，优先用可发现、可校验的原文补证；大任务需要更高摘要额度时，应先补不同位置、多个长任务和重复压缩的固定对照。

原始证据：[context-summary-budget-online.json](context-summary-budget-online.json)。入口：[contextSummaryBudgetVerify.ts](../../eval/contextSummaryBudgetVerify.ts)。

## 费用、验证和剩余边界

实验顺序为第一版回读 → 摘要四档 → 第二版回读；每次继承紧邻上一报告的预算和 SHA，不与其他付费实验并行。累计保守预留从 **$1.406893** 增至 **$2.821485 / $2.929132**，剩余 **$0.107647**；没有新加费用额度，也没有未知生成自动重放。

新增生成共 **131 次**（33 + 64 + 34），全部记录 `completed`。摘要实验 36 次 Token Count 也全部完成。三组生成用量按[官方 Flash 峰价](https://api-docs.deepseek.com/quick_start/pricing/)及缓存折扣估算分别为 $0.057235、$0.049192、$0.065178，合计 **$0.171605**；这是返回用量的估价，不是账户账单，保守预留则按输入计数与最大输出计算。评测进程退出 1 是如实保存未全对结果，不是请求状态不明。
