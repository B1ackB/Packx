# 复核输出预算对照：2026-09-29

**决定：不采用 16384 作为新的默认复核预算。** 该配置在本批开发样本中减少了截断，但没有达到事先冻结的控制质量和动作边界门槛。生产配置未改动。它不是解决所有复核失败的修复，也不能证明真实用户任务成功率提升。

## 授权与设计

用户在本线程明确批准独立上限 **2 美元**的只读模型对照。完成 60 次生成、60 次 Token 计数，无自动重试，无业务写入或审批。沿用 `packaging-requirement-evidence.v2.2`，两组只改变输出上限 8192 / 16384；每个输入每组各两次，交替执行顺序。每次输入最多 24000 Token、120 秒超时，先持久化费用预留再生成。

15 个输入包含 4 个历史截断输入与 11 个控制输入。每组 30 次生成、22 次控制检查；控制中正常样本 4 次、缺陷样本 18 次。排除之前存在未知结果的 `received-limit-83` 和 `clean-control` 输入，保留它们的原请求和全部预留；新批次费用独立核算，没有使用旧实验的剩余额度。

采用条件在执行前冻结：60 次全部完成，候选通过全部 22 次控制检查及所有有效输出的动作边界检查，有效输出数不低于基线、截断少于基线，响应模型标识一致。收到完整 `max_tokens` 终态作为失败保留，可进入下一个预定独立样本；无可信结果的调用必须停止批次。

两组请求及返回的模型标识均为 `deepseek-v4-flash`。根据当天核对的[官方模型与价格说明](https://api-docs.deepseek.com/quick_start/pricing/)，该旧别名由 V4.1-Flash 提供服务，因此仅比较本次两组，不把旧报告当作同一模型版本的历史基线。峰值价格为每百万 Token：未缓存输入 $0.3、缓存输入 $0.006、输出 $1.2。

## 未达标原因

1. `contradiction-control` 两次重复中，16384 都识别出“允许 PVC”与原文“禁止 PVC”的矛盾，却建议 `revise`。现有 Host 只允许指定叙述位置的 omission / unsupported 修订；contradiction 必须转人工。识别到了问题不等于获得修订权限。8192 也存在该问题。
2. `confirmation-not-certification` 的第一次 16384 输出正确指出“产品类型确认不能证明食品接触认证”，但 `evidenceRefs` 是空数组。生产解析器拒绝该输出，诊断为 `invalid_review`。没有从 reason 文本自动补填引用，也没有将这次结果改判通过。
3. `missing-original` 的第一次 16384 输出指出原始资料不可读，但 `insufficient_evidence` 位于 `/nextAction`，与冻结控制要求的 `/facts` 不符；同时建议自动修订 `/missingRequiredFacts`，超出叙述修订范围。因此控制与动作检查均失败。这里应归因为输出合同不符合要求，不能笼统称作完全没发现证据问题。
4. 最困难的 `received-limit-38` 在第一次 16384 调用完整返回，第二次仍然截断。提高上限没有建立稳定完成保证。

本次只生成和检查报告，没有执行模型建议的修订；以上动作失败不代表发生了越权写入。冻结评分、来源和权限保持不变，未根据观测结果放宽门槛。

## 成本与证据保全

`npm run check`：**96 个测试文件、821 项测试通过，21 项条件跳过；类型检查及生产构建通过**。见[校验记录](review-output-budget-2026-09-29/verification.json)。归档另逐项校验 60 次尝试各有一次计数与生成、实际请求只改变上限、所有已知用量可核验、源码及旧证据摘要未变。
