## 实验条件与可声明范围

自动协议包含 12 个合成开发场景、31 个规定检查点，复用作者已见过的开发资料。每个实验臂三次重复，共 36 次尝试；不是 36 个不同任务。模拟确认只发生在实际候选的值、来源和状态已经匹配后，新交付物仍停在应有的人工核对／审批门。模型说“完成”不作为结果依据。

Flash 下比较 2026-09-25 Trial C 生产快照与本轮候选快照，交错顺序执行；两个快照共享相同任务、评分、网络适配器、8192 输出预算、阶段／复核 120 秒超时和工具／循环限制。它比较整组产品改动。墙钟时间包含实验预算守卫额外的 Token 计数请求、落盘和流程开销；确认动作由脚本即时模拟，没有测量真实人工等待。Pro 固定同一候选快照及协议，运行相同案例和重复次数；Pro 在 Flash 后执行，缓存与服务时间不同，不能当作生产延迟基准。响应身份只能证明所记录的模型别名，不能证明服务商后台模型构建版本未变。

有限表示规则在运行前冻结。字符串表示未覆盖时为 `needs_review`，并非自动判错。例如“定稿已提供”与包含后续工艺评估说明的稿件状态，以及日期后附带“到货”，可能需要更完整的字段输出协议或独立语义核对。本轮没有按已经见到的输出添加别名，也没有借助 LLM Judge 改写判定。因此这些数字表示自动协议可证明的完成情况，不是完整语义准确率。

初始 r2 批次在第 4 次尝试遇到 `output_limit` 后按规则停止。代码核查确认该错误来自已经收到的 `max_tokens` 终止响应；业务结果明确失败，但适配器抛错前没有传出用量。后续 r3 仅调整独立尝试之间的停止规则：保留初始报告与全部预留，跳过原有 4 个身份，仅执行原计划尚未开始的尝试；收到相同终止错误时停止该尝试、保留失败并继续独立案例。任务、评分、生产代码和模型预算未改动。网络中断、计数未知或未结束请求仍停止整批。r3 在第 81 次尝试遇到一次连接 `terminated`，远端结果未明，原批再次停止并封存；该请求的 0.0377784 美元上限继续保留。随后基于已有“完成计划＋20 美元总上限”的授权，按唯一请求 SHA 审查独立继续的风险边界：远端只生成响应，不会自行执行本地工具；未收到的响应不会被接受为业务结果。r4 跳过全部 81 个旧身份，只执行原计划剩余 27 个独立尝试，带入累计 6.13365918 美元预留，不重发、不清除未知、不提高预算。新连接错误仍会停止新批。这两项中途停止规则调整均单独记录；这不是从未中断的一次运行，也不代表断线请求已被成功对账。

工具统计另做事后对账：按 Host 执行 ID 与 toolCallId 对齐模型申请、进入下一次请求的 Tool 返回消息和 Trace 完成事件。运行失败时部分完成事件可能缺失。仅当保存的 Tool 消息带有 Host 的 `sourceTool` 元数据时，才按冻结 Loop 的明确契约补证成功状态；该字段只在 `status=succeeded` 时附加，不从工具正文或模型自述猜测状态，缺失耗时保持未知。这里只证明工具返回已写入下一次请求载荷，不证明远端已收到该请求；较早归档中的 resultSeenByProvider 字段也按此边界解读，最终分析已改用 resultIncludedInModelRequest。原始 Trace 与冻结评分均不改写，原记录数、补证数和仍未知数分列。工具调用尝试包含被校验拒绝的申请，不等于全部执行了外部动作。

## 由真实轨迹驱动的最小修复

`flash-candidate-AI-09-2` 返回了同一个 quantity 字段的两项记录：Host 已确认的旧总量 4800，以及客户尚待批准的新总量 6200。模型已经读到了新提议，错误发生在包装需求 Worker：它把旧值回显和唯一新提议统称为多值冲突，跳过了待确认变更的保存。旧权威值没有被覆盖，业务审批也被阻断，但 Artifact 的 `pendingChanges` 缺失，结构化 `nextAction` 仍显示可进入审批。

修复只调整已有候选合并：计算新提议数量时排除与 Host 已确认值严格匹配的回显；唯一有来源的新提议进入 `pendingChanges`，等待明确确认。多个不同的新提议继续保持冲突，未确认历史值也不能享受该规则。值与单位比较复用既有严格逻辑，不猜测语义等价，不按模型输出顺序选择答案。

[同输出回放记录](pending-change-replay-2026-09-26.json)固定原先收到的 12 个真实模型响应，分别经过修改前后生产路径：修改前 3/4 检查点通过、任务失败；修改后 4/4 通过。发生变化的检查点保留 `quantity=4800, verified, version=2`，新增来源为 `RI-09-S02` 的待确认 6200，并阻断审批；后续明确模拟确认才生成正式版本 3。新增的正反顺序回归在修改前均失败，隔离修复后的相关 36 项测试通过；两个不同新提议的反例仍被拒绝。

这是对 Host 状态处理的受控回放，使用历史模型响应、没有新调用；修改后的复核输入可能不同，回放仍固定原复核响应，因此不能把 4/4 当作新的在线成功率。后续单独冻结 AI-09 与 AI-13、各三次的定向在线复测，选择依据是已观察到的故障，属于开发回归，不是预留集或盲测。

六次新尝试全部结束：**0 通过、5 失败、1 待复核**，到达 15/27 个规定检查点。这个结果没有证明修复后的完整任务成功率提高。

## 连续上下文专项

比较提前压缩 32k／20k 与当前 70k／45k，两种 seed 轮换配置顺序。每条序列在同一个 Session 接收六批资料，每批 800 条不同合成候选记录和一份检测记录；完整序列为 4800 条候选记录、102 条新增资料消息。它是控制数据量的压力场景，不代表真实客户流量。

四项当前事实由 Host 提供，检测 code 与 conditions 必须从原文读取。每波检查 8 项答案与规定原文读取行为，摘要、主模型调用、计数和回读均进入账本。只有实际观察到每条序列至少两次压缩，才算覆盖连续压缩。未知请求停止序列并保留费用；已收到的截断或不可解析 JSON 停止该序列，后续独立配置继续，未到达波次单列。

实际结果为 `completed_with_failed_sequences`：四条六波序列均未完成，24 个计划波次中到达 9 个、通过 4 个、失败 5 个、未到达 15 个。只有提前压缩 seed 1 在停止前记录了两次压缩，其余序列分别为 1／0／1 次；不能把整轮标为连续压缩验收通过。

两配置实际到达的数据量不同、失败位置不同，不能用这两个部分费用计算压缩节省率。已返回用量分别为非缓存输入 73,179／159,746、缓存输入 81,024／166,656、输出 6,044／6,210 Token，包含摘要和主生成；四次截断请求的用量仍未取得。本阶段累计已知估价 0.086068 美元、增加预留 0.225684 美元，带入矩阵后总预留 11.804662 美元。

具体失败具有两类不同含义：

- 提前压缩 seed 1 在第二波的主模型 4096 输出预算下截断；其他三条序列分别在第二或第三波的摘要调用中触及既有 512 输出预算。全部保留失败与费用上限，没有重发。只有成功完成压缩且记录完成事件的次数进入上表，摘要中途失败不算一次已完成压缩。
- 当前阈值 seed 1 第二波的原文读取和四项检测信息正确，但数量回答为上一波的 `5101 / 6101`；该请求中 Host 明确提供的是 `5201 / 6201`。这是模型在回答中使用了过时状态，不能归因为当前事实没有进入请求，也不表示持久化权威 Fact 被模型覆写。本次专项仅执行只读回读和结果核对。

有可解析答案的五个波次中，40 项字段检查通过 38 项；四个截断波次没有有效答案，另有 15 个波次根本未到达。38/40 不能当作整个计划的“信息保留率”。四次已记录压缩的摘要覆盖标记全部为 `incomplete`，覆盖计数只表示处理过哪些消息，不证明消息语义保真。由于提早终止，本轮没有验证完整六波、4800 条候选记录的持续执行；每条序列最多到达第三波，实际各波均可追溯。

结论是保留当前生产阈值，不依据本轮不完整结果采用更早压缩。下一轮先解决摘要／主输出截断的可诊断性，并为回答与当前 Host 事实不一致建立明确的结果校验；新策略应另冻任务和代码复测，不能重写这次记录。证据见[专项 manifest](automatic-online-2026-09-26/context.manifest.json)、[完整报告](automatic-online-2026-09-26/context.report.json.gz)和[分项分析](automatic-online-2026-09-26/context.analysis.json.gz)。

没有“不压缩”实验臂，不能计算相对无压缩的净节省；有预先指定的原文索引，不能扩大为任意语义搜索能力。该专项没有覆盖长会话中的来源撤回、全部自由叙述语义和数小时连续业务任务；任务矩阵中的来源撤回也不能替代这些验证。
