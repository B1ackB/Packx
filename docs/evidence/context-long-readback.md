# 长上下文回读重复对照

日期：2026-09-24。起点 `4c8affd`（PR #21）。本轮验证既有来源排序、状态提示与回读路径在长上下文中的表现，生产 Runtime、预算与压缩阈值不变。

## 对照范围

[预先固定的协议](context-long-readback-protocol.md)包含同一合成长任务的三个状态：三轮真实压缩后的原文缺失、旧轨迹中原文已经齐备、旧轨迹中检测正文已经外置。工作消息分别为 82／100／86 条，正文约 15.5／17.3／13.8 万字符；完整快照和原始对话封装在带哈希的 [fixture](../../eval/fixtures/context-long-readback.v1.manifest.json) 中。

每种状态各重复两次，每次比较 PR #20 的冻结 Tool 与 PR #21 的当前 Tool，共 12 组；第二次交换调用顺序。两侧使用相同 `context-readback.v2` 问题、十字段状态 Schema、Host 事实和首轮消息。新旧 Tool 定义与返回格式属于被测差异，不能声称完整 HTTP 请求相同。

全部通过真实 Runtime、持久 Store、ContextEngine、摘要器和 Loop Guard 运行新只读 Turn。两侧允许 64 次工具、32 次主调用、4 次摘要、100k 输入、70k／45k 压缩阈值，每组最长 180 秒。没有继续旧任务的未决副作用，也没有引入按“曾读过”禁止回读的规则。

## 计量与离线验证

严格原文可见性只在已完成生成的实际请求中核对；该指标排除关键词片段、摘要和来源指针。正文已外置后的恢复与正文仍在输入中的重读分开统计。严格指标为假并不代表原文字符没有进入请求：短原要求可能完整出现在查询摘录中，因此另做逐字文本核验，保留两种口径。

`tool.after` 记录实际执行次数，完整 batch 检查点保存工具正文。若 Guard 在批次中止、成功回读正文尚未进入检查点，依赖正文的三项指标为 `null`，并保留缺失的调用 ID。来源重叠只计算完成搜索中已证明的范围，并区分翻页；重叠对数不等于多余工具数。

- `npm run check`：84 个测试文件、668 项通过、21 项按配置跳过；TypeScript 与 Vite 构建通过。
- 新增 6 项回归覆盖 fixture 的三种可见状态、预算和未知账本拒绝、两种嵌套正文恢复、搜索范围与翻页、重读与恢复的区分、成功读取后在检查点前异常停止。
- 最终 12 组确定性离线回放全部十字段通过，28 次 Fake 生成与 28 次 Fake 计数；所有正文计量完整，六对首轮消息哈希相同。原文缺失组为 3 次工具／3 次主调用，原文齐备组 0／1，正文外置组 2／3，后者均识别一次完整正文恢复。Fake 只证明机制，不用于比较真实模型收尾质量或费用。

## 逐次证据与计量边界

独立审查核验了报告、请求压缩文件、12 项源码、5 个生成请求及 5 个计数请求的哈希；使用冻结 Tool 离线重放 7 次读取，输出与保存正文逐字相同。[核对清单](context-long-readback-inspection.json)保留费用与实际请求定位。

- 第 1 轮查 `transcript/PVC` 和 `transcript/sample 4`。PVC 查询的 `items[0].excerpt` 恰好逐字等于 80 字符的完整原要求，并指向 `transcript` 第 0 条。因此第 2–4 次已完成请求都包含完整要求文本。
- 第 3 轮沿快照定位读取检测原文；第 4 次已完成请求的第 92 条消息包含完整 3,679 字符正文，当前 Host 状态也在输入中。请求存档索引从 0 开始：`requests[3].messages[86]` 为完整要求摘录，`messages[92]` 为检测回读正文。
- 第 4 轮仍发出 `sample` 与 `SEAL-9Q7` 两次搜索，结果指向同一检测位置，没有增加本题目标事实。这是证据已齐后继续搜索的一次观察，尚无候选对照或完整最终回答。
- `fullOriginalsVisibleAtIterations=[]` 是“排除 query 摘录”的严格口径，不能解释为原要求从未送入模型。`sameBatchQueryOverlaps=[]` 仅表示没有同批次、同关键词的已证明重叠对；上述不同关键词搜索仍覆盖相同来源。
- 第 5 次保存的请求也含上述文本，但响应为 `unknown`，不计作确认送达。没有发生新的压缩，因此本轮不能证明提高 70k／45k 阈值有收益。
