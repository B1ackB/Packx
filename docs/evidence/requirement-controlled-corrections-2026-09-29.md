# 受限自动修订与提取纠错验证

日期：2026-09-29。当前策略为 `packaging-requirement-evidence.v2.6`，设计见 [ADR-0029](../adr/0029-controlled-requirement-corrections.md)。

修复前 [v2.5 人工介入检查](review-human-routing-2026-09-29.md) 的两份 PVC 阻断已有对应修订路径；明确数量提取错误可生成有来源的未确认候选。系统复核失败单独显示为待恢复。已确认事实、人工录入值、真正来源冲突、计划范围和版本交付审批保持受控。

## 固定旧数据对照

使用原预算实验中保存的输入和输出，未改写原始档案。逐条结果、原始报告摘要和实现/测试文件摘要见 [JSON](requirement-controlled-corrections-2026-09-29.json)。

| 固定用例 | v2.5 行为 | v2.6 离线验证 |
| --- | --- | --- |
| 4 份 PVC 矛盾 + 1 份只标在 `/facts` 的 PVC 遗漏 | 3 份允许修订，2 份整份阻断 | 5 份均可接受受限脚本补丁，保留 Facts，并在文字中保留禁令 |
| 4 份数量提取错误，原文 12000、候选 12500 | 事实字段不可自动修订 | 4 份均由确定性规则生成 12000 的未确认候选，保留来源与旧值 |

这是组件回放：文案补丁来自脚本，未实际购买修订或二次复核调用；数量纠正由当前确定性代码完成。不能把 9 份组件验证称为 9 次真实模型任务成功。新的真实模型调用数为 **0**，新提示词在线准确率、成本收益和真实用户效果均尚未验证。

## 验证结果

- `npm run check`：97 个测试文件通过，874 项通过、21 项环境条件跳过；TypeScript 与生产构建通过。
- `npm run eval:offline`：固定 Harness 校验通过。
- `npm run eval:m2`：需求单纵向流程及确认边界通过。
- `npm run eval:recovery`：离线恢复场景通过。
- `npm run eval:reliability-repairs`：旧事实回答被当前字段合同拒绝，108 份旧尝试、166 个检查点诊断回放完成；无新增模型调用。
- `npm run eval:product`：本地确定性模型的 HTTP/SSE、确认审批、导出、隔离及恢复流程通过。测试需要本机回环端口，不调用真实模型。

关键回归覆盖：混合报告修订后保留真正阻断项，即使第二次复核返回空问题也不能审批；纯 `/facts` 遗漏只追加完整来源引用；无进展补丁和无效复核进入系统恢复；数量范围、样品、每箱、追加、未批准、单位/来源冲突、不可读原文、人工修改均不能触发自动纠错。纠错决定持久化后和事实写入后两处崩溃均可恢复，不重复调用、不重复增加事实版本；其他租户不可读纠错记录；旧生成检查点不静默采用新纠错协议。

## 保留限制

数量纠错只支持当前列明的明确整数件数表达，任意尺寸、价格、认证和材料仍不自动纠正。文案修订最多一次，第二次复核仍有问题就停止。完整短原文引用最多单条 2000 字符，长文及未知语法不猜测。最终事实确认和具体版本交付审批仍然存在。

先前 8192/16384 输出预算实验的失败和费用证据保持原样；它未达到采用门槛，当前默认预算未因此提高。
