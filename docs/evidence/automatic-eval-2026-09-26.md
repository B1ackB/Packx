## 自动协议的具体边界

原 requirement-intake.v1 和四个原预留案例未改动。新套件复用其 12 个开发场景，明确标为合成、作者可见资料；不能称为新盲测集。AI-09 移除模拟新审批，将起点改为已确认事实；旧审批失效另由故障／事件实验验证。AI-09、AI-13 要求实际保存新提议及其当前 Fact 版本和新来源。

评分采用冻结的有限表示规则：例如 `pcs` 与规定中文单位、数值字符串、规定地区名称和尺寸符号。未知措辞保持 `needs_review`，不临场添加别名让模型输出通过。没有引入 LLM Judge。生产证据复核仍是被测流程的一部分，但不作为最终任务评分者。

模拟确认只在候选值、来源和状态已通过检查后执行；不会预填答案。新协议不批准待语义核对的交付物。来源 ID 匹配只证明关联，语义蕴含仍未评估。此处完成终点是“规定结构化状态已形成，保留人工核对边界”。

## 已冻结的在线实验

- [矩阵计划](automatic-eval-2026-09-26/matrix.plan.json)：Flash 下 12 案例 × 新旧两版 × 3 次 = 72 次任务；交错版本顺序。第二模型 Pro 固定候选版本，同 12 案例 × 3 次 = 36 次。一次任务可能包含多次模型调用。
- 基线为 2026-09-25 Trial C 的已归档生产源码，候选为本轮当前源码；两边共享相同执行器、评分、网络 Provider Adapter、8192 输出上限、阶段及复核 120 秒超时、工具和循环预算。它比较整组产品改动，不能归因于单个机制。已用相同 Fake 参考案例验证两个冻结入口，[记录](automatic-frozen-smoke-2026-09-26.json)不含真实模型结论。
- [候选源码快照](automatic-eval-2026-09-26/candidate.source.tar.gz)与历史基线归档分别留存；源码、依赖清单、任务、价格和执行文件的哈希写入计划。独立本地目录为 `temp/requirement-automatic-2026-09-26-r2/`，报告尚不存在。
- 记录全部尝试、未开始数量、待判／失败／未知、每案例三次结果、生成／计数／工具、Token、时间、成本及错误码。全部尝试已知成本除以通过数，无通过时不计算；未知用量不当零。活动尝试单列，进程中断时不能因尚未归档而悄悄消失。
- 费用按[官方价格页](https://api-docs.deepseek.com/quick_start/pricing/)的峰值口径估算，价格核验日期写入计划；不是账单。请求别名及响应模型身份分别保存；别名相同／映射信息不足时不能宣称两个独立模型已完成比较。费率与别名判断同时参考[官方更新记录](https://api-docs.deepseek.com/updates/)。
- 每次请求先持久化预留，结果未知立即停止整批，既不释放预留也不自动重发。历史 8 个未知记录及原累计预留引用保留在计划中；它们属于此前批次，不冒充本轮已用额度。

本地准备已经完成。下面是执行接口示例，`USD_CAP` 必须替换为本轮明确的总上限；不是默认授权 20 美元。

```sh
npm run eval:requirement-automatic -- --online --directory temp/requirement-automatic-2026-09-26-r2 --usd-limit USD_CAP
```

该批次拒绝重复启动。运行目录含请求、响应与全部状态；不可只发布通过的子集。失败分析后需要修复时，另建有新代码哈希的批次，并保留旧批次。

## 连续上下文实验

[冻结计划](automatic-eval-2026-09-26/context.plan.json)比较提前压缩 32k／20k 与当前 70k／45k；每条序列在同一 Session 中接收六批独立合成记录，每批 800 条不同候选记录及一份检测记录。它是控制资料量的压力场景，不代表真实客户资料分布。

Host 当前事实单独提供；原始检测 code 与 conditions 从对话原文读取，不进入 Host 答案。每波检查当前确认量、待确认量、材料限制、供应商状态及最早／最新检测记录，并验证本波确实读取所需的原文位置。它检验已知索引的回读，不能扩大为任意语义搜索能力。

真实运行必须观测到每条序列至少两次压缩，否则标为 `completed_insufficient_compaction`，不声称多次连续压缩已验证。完整请求账本同时记录摘要、主调用、回读、计数和覆盖信息；比较整条序列总成本。没有“不压缩”实验臂，不计算相对无压缩的节省比例。来源撤回与历史绑定失效由现有 `contextLifecycle` 等离线契约测试覆盖，本实验不冒充其真实模型验证。

若前一个任务矩阵正常结束、无未知调用且还剩预算，可在**同一总额度**下继续；`--prior-report` 会带入该批全部预留：

```sh
npm run eval:context-continuous -- --online --plan temp/context-continuous-2026-09-26-r2.plan.json --report temp/context-continuous-2026-09-26-r2.report.json --usd-limit USD_CAP --prior-report temp/requirement-automatic-2026-09-26-r2/report.json
```

有未知调用时此入口拒绝继续。源代码发生变化也会拒绝按旧计划运行；必须新冻结并披露变化，不能覆盖旧报告。

## 故障验证给出的答案

| 窗口 | 实测结果 | 技术判断 |
| --- | --- | --- |
| 模型返回后、Session 保存前 SIGKILL | 原请求已生成一次；恢复同一请求又生成一次 | 模型费用没有 exactly-once 保证；遥测不等于可恢复的业务提交 |
| 回复保存后、completed Trace 保存前 SIGKILL | 恢复返回 `context_failure`，新增生成 0 | 证据不完整时停止，未实现自动补写 Trace |
| 入队后、Outbox ACK 前 SIGKILL | 恢复发布原 Job，重复 Job 为 0 | 确定性 Job 身份处理重复投递；不代表 Outbox 有全局重试上限 |
| 旧 Worker 阻塞至租约过期，新进程接管 | 旧提交返回 `lease_lost`；接管后只有 1 个 Artifact 版本 | 本地业务提交被租约校验拒绝；不是远程副作用的 fencing 协议 |
| 事件重放、缺正文、未知事件 | v2／v3 文件格式重建同一聚合；旧审批失效、旧 Artifact stale；未知事件及缺 blob 被拒绝 | Event 重建业务聚合；正文等仍需独立存储，不重放外部副作用；未构造通用业务事件迁移框架 |

本地文件副作用的两个提交窗口和外部修改情形已有[单独记录](process-recovery-2026-09-26.json)：证据匹配则对账，重复写入 0；外部修改保持未决。原生 30 项覆盖进程组终止及 Host 强制结束后的子进程清理。网络请求的取消只验证 Host 停止等待和拒绝迟到提交；没有验证远端推理终止或退款。
