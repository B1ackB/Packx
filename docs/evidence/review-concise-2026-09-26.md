## 诊断与候选

上一轮 9 个截断响应均到达 8,192 输出 Token 上限，实际输入仅 1,900–2,846 Token（含缓存）。39 个有效响应的可见正文长度中位数为 280 字符，计费用量中的输出 Token 中位数为 1,358。两个中位数不是逐条 Token 转换关系；现有返回没有可靠拆分可见输出与推理，不能推断截断前具体生成了什么，也不能把原因直接归为上下文长度。

本轮假设：冗长、重复的复核指令可能诱发反复核对，精简任务表述与报告要求有机会减少截断。候选在包装 Domain Policy 中将说明由 2,896 字符／356 个空白分隔词改为 2,232 字符／267 词，版本标识为 v2.4。它要求逐项比较原始客户要求、合并重复发现、用一句短理由报告，并纳入简短的位置与动作规则。这是整段指令重写与动作提示的组合，不能把效果单独归因于字符数减少。

完整证据、客户要求、候选需求单、事实版本、确定性检查、通用 Host 指令和输出 Schema 均不改变。模型仍为 DeepSeek V4 Flash，默认推理、8,192 输出上限、空工具集合。未移除矛盾或缺证据检查，未减少审批，未引入新 Loop、多 Agent、自动重试或后处理纠正。
