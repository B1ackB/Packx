# 长上下文回读验证协议

日期：2026-09-24。起点：PR #21 合并后的 `4c8affd`。本轮先固定数据、比较版本与边界，再执行在线实验；不改生产策略。

## 固定输入和对照

已将原合成长任务封装为可移植、带 SHA-256 的 [fixture 清单](../../eval/fixtures/context-long-readback.v1.manifest.json)及压缩数据。三种状态来自同一长任务，不是三个独立业务样本：

| 状态 | 工作消息 | 正文字符 | 验证目标 |
| --- | ---: | ---: | --- |
| 原三轮压缩之后 | 82 | 154,610 | 沿多层归档找到缺失的原文 |
| 原文已经齐备 | 100 | 172,573 | 是否及时回答，是否继续查相同证据 |
| 回读正文已被外置 | 86 | 137,944 | 识别并完成必要恢复，不将其误判为无用重复 |

后两种状态分别来自旧 42 次工具轨迹的第 5、9 次主请求前。只导入当时已经存在的快照，transcript 使用查询前的原始对话，不导入后来的最终答案。每组以新只读 Turn 重新核对；这不是恢复原任务未决副作用的测试。

比较 PR #20 的冻结 Tool 与 PR #21 的当前 Tool。Runtime 本体在这两个提交间相同，冻结副本只调整导入路径；其余共同依赖不变。两个版本均通过完整 BlackxAgentRuntime、FileAgentStateStore、ContextEngine、摘要器及原有权限／来源校验路径运行。

两组都使用 `context-readback.v2` 的明确状态 Schema 和同一问题；原布尔评分不重算。每种状态各做两个重复，每次包含旧／新各一组，共 **12 组**；第二个重复交换版本顺序。重复采样无固定模型随机种子，不能据此估计生产总体成功率。

## 运行边界与预算

每组沿用生产上限：32 次迭代、64 次工具、主请求最多 100,000 输入／4,096 输出 Token，压缩阈值 70k／45k，摘要最多 4 次、每次 6,000 输入／512 输出 Token。每组最长 180 秒。只用合成上下文和内置只读恢复工具；未知模型或计数结果立即停止后续全部在线请求，不自动重试。

按已核实的 Flash 峰价、忽略缓存折扣计算，每组最坏保守预留：

```text
32 × (100000 × 0.30 + 4096 × 1.20) / 1000000
+ 4 × (6000 × 0.30 + 512 × 1.20) / 1000000
= $1.126944
```

12 组最坏新增预留 **$13.523328**；继承已用预留 **$2.840384** 后为 **$16.363712**。因此建议累计封顶 **$17**。若只做每状态各一次、共 6 组，最坏累计为 **$9.602048**，可封顶 **$10**。这不是预计账单；实际用量、缓存计价和保守预留必须分别报告。

原累计上限为 **$2.929132**，剩余预留 **$0.088748**。用户在本轮明确选择累计封顶 **$17**、12 组对照；新台账继承已用预留 **$2.840384**，不从旧报告重新计算可花额度。先通过离线验证和独立预审，再开始在线请求。

## 记录与判定

- 答案按固定十字段精确评分，保留未知、失败和未完成结果。
- 在实际模型请求中检查完整原要求、原检测正文和 Host 状态是否可见；摘要、片段和引用指针不当作完整正文。
- 上述严格指标统一排除 query 摘录。若短原文恰好全部出现在摘录中，另行逐字核验并报告，不能把严格指标为假解释为原文字符从未进入请求；保存但响应未知的请求不计作确认送达。
- 逐次记录已执行工具、失败、同批次同关键词的来源范围重叠、证据已齐后的额外工具／模型轮数。
- 将“正文仍在时再读”与“以前读过但正文已外置后的恢复”分别统计；不根据工具参数相同就禁止读取。
- 工具已成功执行但异常停止导致检查点没有保存正文时，记录缺失的调用 ID，并将依赖正文的三项指标设为 `null`；实际工具次数仍由完成事件计数。来源重叠只统计完整搜索已证明的范围，不能把未完成搜索当成没有重叠。
- 保留摘要覆盖、压缩次数、最终停止原因、主／摘要生成、计数、Token、缓存、耗时、预留和用量估价。
- 原始请求和输出作为压缩合成证据保存；校验 fixture、源码、首请求、继承台账的哈希。已有报告禁止覆盖。

离线固定回放先验证输入完整性、路径和计量，不当作真实模型自主收尾改善证据。完成后再独立核对原始记录，并决定后续是否值得修改批次调度。
