# Requirement intake execution and scoring v2 — 2026-09-25

Input cases, oracle facts, source hashes, split and expected business outcomes remain the frozen `requirement-intake.v1` manifest. This file versions the execution/scoring changes after the first real-model trial; it is included by SHA-256 in every v2 report and never sent to the model.

The initial v1 attempt of RI-01 stopped after its first checkpoint. Its production evidence-review call returned the adapter error `output_limit` at 4,096 output tokens; the ledger conservatively retains `unknown` because it has no saved successful response or usage. The scorer also rejected quantity unit `个` against the fixture's canonical `pcs`, although both described 3,600 individual cans. The original report, code, request and full USD 0.0167925 reservation must remain unchanged. It is not a passing task or a completed baseline.

V2 changes, declared before starting a fresh 12-case development batch:

1. All non-identical units require explicit semantic review with the actual value, actual unit, expected value, expected unit and original source. `个` / `张` / `pcs` can be accepted when they denote the same counted item. Rolls, boxes of multiple items, or unsupported conversions must not be accepted as individual-piece counts. Numeric values still compare exactly; a wrong or missing number remains a deterministic failure. A review cannot override that failure. The same review rule previously used for string-valued dimensions now also covers numeric counts.
2. The eval-only output reservation and provider maximum become 16,384 tokens instead of 4,096. No production Prompt, Skill, fact rule, tool, reviewer or Core implementation changes. All 12 cases use this same setting. Production per-turn timeouts remain unchanged and any resulting timeout is reported.
3. A reviewed-stop continuation may retain the first report by hash and carry all its reservations, including the unresolved call. It is a new trial with new isolated state and changed output request, never a resumption or replay of the ambiguous execution. The original unknown is not reconciled or relabelled. The user authorized paid evaluation and raising limits on 2026-09-25; the operator chose a cumulative USD 20 ceiling. V2's theoretical 12 × 32 × (100,000 input at USD 0.30/M + 16,384 output at USD 1.20/M) is USD 19.0697472; adding the initial reservation gives USD 19.0865397, below that ceiling.

Semantic review is `codex_assisted` unless an actual human provides it; it is unblinded, performed by the case author and uncalibrated. Separate it from deterministic checks and do not call it an independent human gold judgment. Report v1 and v2 separately; a score difference between different scoring/output protocols is not an improvement attributable to Harness changes. The 4 holdout cases remain unused.
