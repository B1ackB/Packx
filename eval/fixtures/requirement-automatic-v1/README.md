# 结构化包装需求自动任务 v1

这是独立于完整语义评测的窄范围协议。12 个任务复用 requirement-intake-v1 的全部 12 个开发案例，31 个检查点；不使用 4 个预留案例。案例是作者已知的合成资料，不是独立金标准、盲测或真实用户订单。

完成定义：任务全部规定检查点的结构化字段、单位、确认状态、来源关联、缺口、待确认变更、版本及审批状态满足 oracle，且真实执行结束。任一失败、未到达或无法规范化的表示均不能算通过。分别报告 failed / needs_review / not_started / unknown，不抹除中间错误。

模型只接触 task、当前 request、已经到达的消息／附件、真实 Host 状态。评分文件、字段答案、未来事件和 normalization.json 不进入模型请求。自动协议复用真实 RequirementBriefWorker、Runtime、Tool、Outbox、Queue、Artifact 与 Event 存储；每次尝试独立作用域和目录。

## 与原协议的明确差异

- ID 改为 AI-*，原来源与事件 ID 保留以便追溯。输入原文不改写。
- 不评价自由叙述的完整、自然、语义蕴含或额外待办是否恰当。原协议仍保留这些要求；本协议通过不能写成原协议完整任务通过。
- 不注入人工／Codex 复核结果，不使用 LLM Judge。有限表示等价按 normalization.json 和评分器固定规则；未覆盖措辞为 needs_review，不能根据本轮输出临时加别名。
- AI-09 去掉原来的新交付物审批事件，approved_base 改名 confirmed_base。它验证已确认事实上的变更，不声称在此在线流程完成“已批准订单”测试。旧审批失效由独立恢复／事件实验覆盖，不以无人评分绕过审批。
- 仅当模型已正确提取同值、单位和有效来源的候选时，原模拟员工确认才可执行。不能用 oracle 补齐遗漏；确认只表示本合成脚本的授权输入。
- 待确认数量变更必须存在 Host-owned pendingChanges，旧 verified 值保留且 nextAction=confirm_facts。这是共同业务要求，旧候选缺少结构化提议可以真实失败；不从说明文字补造结构。
- 结构化额外字段、重复字段和未授权 approved 状态均失败。来源检查是关联与有效性验证，不等于全文语义支持。
- 附件仍为文本／元数据，不能称作 PDF/OCR 实验。多阶段分别启动 Session，不称作单条持续模型会话。

## 表示规则与评分器验收

NFKC、空白、大小写与乘号格式可统一；枚举别名只取冻结表。quantity/material_thickness 可接受严格十进制数字字符串，不做跨量纲换算。尺寸可将单独 mm 单位拼回原维度文本，保留数字次序、内外口径及维度标签；不能丢掉冲突单位。

评分器须对全部 31 个参考检查点接受已知结构结果，并拒绝数量、单位、来源、确认状态、缺失集合、重复字段、审批和待确认变更破坏；未知措辞不得自动判对。参考结果由 oracle 构建，仅用于评分器资格测试，不提供给真实模型。离线 Fake 运行只检查执行链，不计真实模型成功。

## 对照与记录

首批为归档 Trial C 代码与本轮冻结候选代码，使用同一自动评分器、模型、上下文、轮数和超时。每案例 3 次，交换两臂顺序，共 72 次尝试。比较的是组合改动；不能归因于某一个机制。预算不足、未决外部请求或存储异常必须停止，不更换目录隐藏已发生请求。

报告包括输入／代码／评分哈希、调用用途、实际模型信息、计数与生成请求、Token、保守预留、已知用量估价、任务和工具耗时、完整状态／来源／版本检查及未到达检查点。旧实验 unknown 和预留作为独立历史引用保留，不重放，不混成新预算。

所有自动检查全过才记本协议通过；任务成本包含失败、生产复核、摘要和重试。模拟确认次数不是人工工时；重复 3 次仍然只有 12 个任务家族。
